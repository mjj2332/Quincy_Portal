Project header

The project page opens with the work, not the paperwork. Everyone on a project needs its name, its stage and its deadline at a glance, and the collection tabs one tap away. The rest (client, shoot, Dropbox, reminders, notes, links) moves one layer down: a sheet from the right on desktop, a sheet from the bottom on the phone.

  • Glance, then go deeperName, Stage, Deadline and Team stay in view. Every other fact is one click or tap away.
  • Tabs are the main controlOn the phone the tabs stick to the top while the project bar scrolls away. Switching collections never needs a scroll back up.
  • Problems show up, normal states stay quietDropbox appears in the header only when it is blocked. Overdue, archived and read-only states change what the controls look like.

Rail visible · 772px and wider

Desktop

Two rows replace today’s three bands. Row A holds the identity and a cluster of status controls. Row B holds the collection tabs. The shell bar’s breadcrumb already says where you are, so the “← Dashboard” crumb inside the header goes.

iPad portrait · 834px

Tablet

Same two rows. When the identity and the cluster no longer fit on one line, the cluster wraps under the title and Details stays at the right edge.

Below 772px · iPhone 15, 390 × 844

Phone

A single project bar names the project and shows its stage and due date. Tapping it opens Project details in a bottom sheet. Editing happens in views pushed inside that sheet, so a popover never has to squeeze in beside the on-screen keyboard.

Try it

This phone works. It shows the intended behaviour, not the final build.

  1. Scroll the photos. The project bar scrolls away, the tabs stick under the shell bar, and the project name moves into the shell bar.
  2. Tap the project bar, or the name in the shell bar, to open Project details.
  3. Tap Stage, Deadline or Team to edit in a pushed view. Changing the Stage updates the bar straight away.
  4. The board icon at the end of the project bar opens the whiteboard. It is also the first action in the sheet.
  5. Close with ×, by tapping outside the sheet, or with Esc.
Considered, not recommended

Alternative: the name lives in the shell bar

This drops the project bar completely. The tabs sit right under the shell bar, which always shows the project name as the button that opens the sheet. It saves 62px at rest but hides the Stage and the due date until you open the sheet. That costs most on the phone, where people check them on site.

Your call before the build

Decisions for the owner

  1. Production notes go behind a link.On desktop they become a “Production notes” link in the meta line; on the phone, a note icon in the project bar. Both open the details sheet with the notes at the top. The alternative is a one-line excerpt under the title, which costs about 22px.
  2. Dropbox leaves the always-visible row.Its status and its Open and Sync actions move to the details sheet. A caution “Dropbox blocked” chip joins the cluster only while autoHDR is blocked (D6).
  3. Edit details, Copy link and Show in move into ⋯ on desktop.On the phone they sit at the bottom of the details sheet.
  4. The phone shell bar gets a title slot.At rest it shows only the parent (“Dashboard”), because the project bar names the project. Once the project bar scrolls away, the project name fades in there and becomes a second way to open the sheet. This is a change to ShellHeader, not only to the project page.
  5. The field labels go from the desktop cluster.“Stage”, “Team” and “Deadline” are no longer printed. Each control carries an icon or a dot, a tooltip and an accessible name. Prototype 2a printed them; this version gains a whole row by dropping them.
  6. The desktop details sheet is modal.The other choice is a docked panel that pushes the photo grid aside and stays open between visits. A modal sheet is simpler and matches the Project sheet the Dashboard already opens.
