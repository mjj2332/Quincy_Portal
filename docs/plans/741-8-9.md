## Settled decisions (these OVERRIDE anything in the body below)

1. **Gate:** both `notes` AND `export` parts (deep). An export of notes with the notes part off is meaningless; one gate read via `admit`'s part list (`extraParts`) in `video-notes.ts` style. Closed → 404.
2. **Archived Projects still export** (deep). Export is a read, like every other video read; no 409. A test pins it. Route order: gate 404 → `viewVideo` 403 → visibility → query 400 → Version 404 → EDL >999 422.
3. **Export options are independent of the notes-panel filters** (Codex). Query `format=edl|fcpxml` (required), `includeInternal=true|false` (default false), `status=all|open|resolved` (default all). Internal notes are never in an export unless explicitly ticked (story 56). Settings are never persisted.
4. **Tombstoned roots** (deep, matches the panel and open counts): a deleted root with no live replies is excluded; a deleted root that still has live replies exports as a marker named "Note deleted" with its live replies folded in, so no feedback disappears. Deleted replies are always excluded. Visibility and status filter by the root.
5. **Out-of-range frames:** fail loud with 422 `export_frames_out_of_range` (Codex); never clamp or drop silently.
6. **Menu placement:** the notes panel's existing ⋯ menu (`components/quincy/menu.tsx`) gains an "Export markers" group (deep): an "Include internal notes" checkbox (unchecked), "All / Open only / Resolved only" radios, and two format items with a filename preview. The ⋯ menu renders when the person can copy notes or export. Export is **hidden in compare mode** for this slice (Codex). Client-side marker count from the same shared selection function disables EDL above 999 with a hint; the server's 422 still covers races.
7. **Response headers:** `X-Marker-Count` (deep's name). Everything else per the Codex body (§4): content types, `private, no-store`, `nosniff`, RFC 5987 filename via one shared builder, 422 `too_many_markers`, zero markers → 200 valid empty file.
8. **Shared selection:** one function in `@quincy/shared` (`exportNotesFromThreads` or equivalent) turns note rows into `ExportNote[]` with the rules above; the worker uses it, and the web uses it for the count preview. Do not duplicate the rules.
9. **Audit:** one `video_note.export` row per successful GET (both plans); no activity row; no note text in meta.
10. **Who:** Admin, Editor, assigned External editors (they already read internal notes); Photographers 403 via `viewVideo`. No guest route, no MCP tool.

PR 8 = `feat/741-marker-export-api` (now). PR 9 = `feat/741-marker-export-menu`, after 6b-ui merges; ordered against 7c by whichever is ready first, and the second rebases (collision: `VideoCollectionPanel.tsx` props, `VideoNotesPanel.tsx` menu).

Owner (Seam 3, does not block merge): import the pilot EDL into Resolve and the FCPXML into Final Cut; files saved under `qa-evidence/741-8-9/`. `export` stays dark until accepted.

## 2. Endpoint and admission

`GET /api/projects/:projectId/video-versions/:assetId/marker-export`

`:assetId` is the Version's video Asset ID, including superseded Versions.

| Query | Accepted values | Default |
|---|---|---|
| `format` | `edl`, `fcpxml` | Required |
| `includeInternal` | `true`, `false` | `false` |
| `status` | `all`, `open`, `resolved` | `all` |

Reject unsupported values, unknown parameters and repeated parameters with 400.
No note-ID selection, pagination, custom timecode, or client-supplied export context.

Admission order:
1. Existing session middleware: unauthenticated callers get 401.
2. Malformed Project/Asset UUID: 400, following existing video routes.
3. `videoReviewGate(..., "export")`: closed 404 `{ error: "Not found" }`.
4. Existing `viewVideo` capability: 403 `{ error: "Forbidden" }`.
5. Project visibility: External 404; staff 403 using existing access responses.
6. Archived Project: staff 409 `project_archived`; External concealed 404.
7. Query validation, then scoped Version lookup and selection.

The archive refusal is an explicit export-specific rule requested for this slice.
Ordinary note GETs continue permitting archived reads.

- Gate only on `export`; neither `notes` nor `markup` must be enabled.
- Reuse `VIDEO_REVIEW_PART_CAPABILITY.export = "viewVideo"`.
- Admins and Editors, including staff doing QA, may export.
- Assigned External editors may export: export supports their existing review work.
  Assignment scope stays enforced; this grants no links or Release capability.
- Photographers cannot export. Client/guest tokens cannot authorize this route.
  No export route is added under `/d/*` or to the MCP allowlist.
- Every admitted role currently reads internal video notes.
  `includeInternal=true` is an explicit opt-in, not an additional grant.
  A caller without internal-note access must receive 403 for that option;
  never silently downgrade it or return internal content.
- Register with `terminalRoute`, inline checks, and a manifest seed.
  Do not add router-wide `.use("*", ...)`.
- Manifest classification is scoped child resource / external-safe.
  Do not assign a JSON `externalSurface` to this file response.
- Implicit HEAD follows admission and file headers, returns no body and no audit.
  Unsupported methods/trailing-slash paths retain the API terminal fallback.

## 3. Selection and export context

Use a dedicated lean loader in `workers/app/src/lib/video-marker-export.ts`.
Read Version metadata, Video title, eligible roots and replies in one SQL statement.
Anchor on the scoped Version with LEFT JOINs so zero notes still returns a Version.
Include the Project archive state in that snapshot and recheck before conversion.

- Scope through `video_version_meta`, video-kind `assets`, and `videos.project_id`.
  Scope note/root joins to the same Project, Video and Version.
- Exclude roots with `deleted_at`; exclude their entire reply threads.
- Exclude deleted replies. Never export “Note deleted” placeholders.
- Select visibility by the root; replies inherit it.
  Apply the root visibility predicate in SQL, before returning export rows.
- `status=all` includes resolved and open roots.
  Other values filter roots by `resolved_at` before same-frame merging.
  Keep every live reply of each selected root, regardless of reply metadata.
- Read the complete selected set. No LIMIT or hidden truncation.
- Map author labels as existing note DTOs do: staff name or guest display name.
  Map `createdAt` to integer milliseconds and resolution to a boolean.
- Drawings remain outside the text marker export.
- Validate selected root frames before calling `buildMarkers`:
  integer `0 <= startFrame < frameCount`;
  a range has integer `startFrame < endFrame <= frameCount`.
- Invalid selected roots fail the whole request with 422:
  `{ error: "Some notes are outside this Version.",
     code: "export_frames_out_of_range", count, frameCount }`.
  `count` counts invalid selected roots. Never clamp or silently omit them.

Context comes only from stored, server-probed Version metadata:
- Exact `{num, den}` fps, nominal/DF base, upright dimensions and frame count.
- `startFrames = start_tc_frames ?? timecodeToFrames(
    DEFAULT_EXPORT_START_TIMECODE, base)`.
  Preserve a real source start of zero. Never use duration, browser fps or player TC.
- Missing tmcd defaults to 01:00:00:00, calculated on that Version's TC base.
- Title is the Video title plus ` · v<N>` to identify the exported Version.

Call the existing `buildMarkers`, then `toResolveEdl` or `toFcpxml19`.
Same-frame merging, reply folding, maximum range duration and resolved aggregation
remain owned by the existing module.

## 4. Responses, filenames and audit

| Format | Content-Type | Extension |
|---|---|---|
| Resolve | `text/plain; charset=utf-8` | `.edl` |
| Final Cut | `application/xml; charset=utf-8` | `.fcpxml` |

Success:
- 200 attachment; existing UTF-8 serializer bytes, no added BOM.
- `Cache-Control: private, no-store`; no ETag, Last-Modified or 304 path.
- `X-Content-Type-Options: nosniff`.
- `X-Quincy-Marker-Count: <post-merge count>`.
- Apply `private, no-store` to error responses too.

Filename:
`<safe-title>-v<N>-notes-<status>-<public|with-internal>.<extension>`

- One shared filename builder supplies the menu preview and server filename.
- Normalize title to NFC; remove controls/bidi controls; replace filename separators
  and reserved characters; trim leading/trailing dots/spaces.
- Bound the title to 120 UTF-8 bytes without splitting a code point; fallback `video`.
- Header contains a quoted, sanitized ASCII `filename` fallback and
  `filename*=UTF-8''<RFC-5987-encoded Unicode filename>`.
- Server header is authoritative; never interpolate an unsanitized title into it.

EDL overflow:
- Translate the existing serializer refusal to 422 JSON:
  `{ error: "Resolve EDL supports at most 999 markers.",
     code: "too_many_markers", format: "edl", count, limit: 999 }`.
- Count after filtering and merging. No chunks, partial file, or attachment header.
- FCPXML has no application marker-count cap; ordinary Worker resource limits apply.
- Zero markers returns 200 with the valid empty EDL/FCPXML and count header `0`.

Audit:
- Follow existing attachment-download audit practice.
- After successful generation, await one `video_note.export` row, target `asset`.
- Meta: `projectId`, `videoId`, `version`, `format`, `includeInternal`, `status`,
  `markerCount`, `startTimecodeFrames`.
- Use the existing audit helper, including impersonation provenance.
- No note text, names or drawings in meta. No activity row or notification.
- Record zero-marker GETs; record no refused/failed export or HEAD.
- The audit records file preparation, not proof of receipt or NLE import.

## 5. Menu and download UX

Place **Export notes** in the single-view viewer header beside the Version selector.
Export the selected Version. No row menu or notes-panel dependency.
PR 9 exposes no export control in compare mode; return to Single view first.

Menu:
- “DaVinci Resolve markers (.edl)”
- “Final Cut Pro markers (.fcpxml)”
- “Include internal notes” checkbox, initially unchecked.
- “All notes”, “Open notes only”, “Resolved notes only” radio choices; All initially.
- Show the exact proposed filename as wrapping secondary text in each format item.
- Export settings are independent of notes-panel filters.
- Option changes keep the menu open; format activation closes it and starts download.
- Settings reset on Version/person/Project change. Never persist internal opt-in.

Render only when capability-intersected `review.parts` contains `export`.
On archived staff Projects, keep the control disabled with visible read-only copy.
Do not infer export availability from whether the notes panel exists or is loaded.

Download:
- New helper uses same-origin fetch with `credentials: "include"` and AbortSignal.
- Check status and parse typed JSON errors before creating a Blob.
- Read filename from Content-Disposition and marker count from the response.
- Create a temporary object URL/anchor only after success; trigger download,
  remove the anchor, and revoke the URL after the download handoff.
- No direct endpoint `<a download>` that turns an error response into a file.
- Disable duplicate requests and announce “Preparing export…” with `role="status"`.
- Capture Version/options at activation. Abort and fence completion on Version,
  Project, principal, gate/mode change, or viewer close; no late download.
- Reuse principal termination/project invalidation helpers for 401 and access loss.

Messages:
- 422 overflow: “This export has {count} markers. Resolve EDL supports up to 999.
  Download FCPXML or choose fewer notes.”
  Provide “Download FCPXML” using the same captured options, plus the menu filters.
- Other 422: “Some notes are outside this Version. Export could not be created.”
- 404: “Export is unavailable. Refresh this Project and try again.”
- 403: “You don’t have permission to export these notes.”
- 409: “This Project is archived. Notes cannot be exported.”
- Network/5xx: retryable “Export could not be downloaded. Try again.”
- Zero: download the empty file and announce
  “No notes matched these export options. An empty file was downloaded.”

Use the viewer's existing overlay container and menu keyboard behavior.
Generalize its capture-time Escape snapshot to inspect inner layers with notes off:
first Escape closes the menu; subsequent Escape follows existing form/viewer order.
Keep player keys from acting on menu-owned input; preserve drafts and playback.

Phone:
- Same menu and choices; no submenu, hover-only action or new sheet.
- Header wraps; trigger/items have 44px minimum touch targets.
- Popup remains inside viewport width/height; long filenames wrap.
- Pending/error Notices remain visible in the viewer's scrolling layout.
