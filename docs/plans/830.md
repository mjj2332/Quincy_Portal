# #830 — Board sort: Shoot date or Deadline (Display menu)

Settled from blind Opus + Codex plans; they agree on everything below.

## Decisions
- Choices: **Shoot date** (default) and **Deadline** (`deadlineAt`). Label "Deadline", not "Due date": `packages/shared/GLOSSARY.md` lists "Due date" under Avoid; the card, Table and Calendar already say Deadline.
- Priority no longer orders cards in either mode (owner). Chosen date ascending → street collator → id. Null/invalid/non-finite dates last.
- Stored per browser in `quincy:dashboard:kanbanSort` ("shoot-date" | "due-date"); every legacy/unknown value (incl. "priority-shoot-date") reads as "shoot-date"; storage failures tolerated. Initial state via `useState(() => initializeKanbanSortMode(...))` so the first render already uses it.
- All roles, External Editors included, get both choices (their DTO already carries the deadline).
- A sort change snaps into place (FlipScope skips/cancels on a mode change); date-driven refetch reorders keep the existing FLIP.
- No sort change during a drag/confirmation/pending move: the Display trigger is already disabled then; also guard the handler.
- No API/DTO/migration change. Server's deprecated order maps stay (removed under #476).

## Changes
- `packages/shared/src/board-order.ts`: `deadlineAt?` on `BoardCardOrderKey`; `date?: "shoot" | "due"` option; omitted mode keeps old behaviour only for the deprecated server maps.

- Docs: GLOSSARY Board definition; lessons.md "Board order is a viewer's choice (#830)" (Tags: board-dnd) + pointer from the #470 entry; `kanban-flip.ts` comment.
