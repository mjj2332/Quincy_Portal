# #787 slice 7: photo zips on the public Client Delivery page (settled plan)

Synthesised 2026-10-12 from two blind plans (Opus deep-reasoner, Codex). Both agreed on the shape; differences are resolved below. Supersedes the "Zips" row of `787.md`, which predates the native writer from #802.

## Decisions
- **One writer:** the native writer only (`lib/zip-native.ts`). `assessZip` gains an opt-in `nativeOnly` option (default false, existing callers unchanged): missing CRCs answer `preparing` and queue work even for small sets; with `native_zip` off a delivery zip answers 502 `download_unavailable`.
- **Sizes:** Web-size streams the current-spec `delivery_web` rendition; Full-res streams the original. A missing or stale Web-size derivative means `preparing` (and prepare re-enqueues it); never substitute the original, never leave it out silently.
- **CRCs:** (1) Publish enqueues CRC work for the set's photo originals after commit, detached, best effort (pattern: `video-approval.ts`). (2) `workers/background/src/renditions.ts` upserts `object_crc32` for a `delivery_web` object right after it writes or adopts it (crc32 over the bytes it already holds, bytes, R2 etag), in try/catch so a failure never fails the rendition. (3) The hourly sweep's ELIGIBLE set gains every photo in a page's current set (locked included, superseded members included): its original and its current-spec `delivery_web` key. That is the repair path.
- **Scope of a zip:** photos only, the page's current set, published order. Unlocked premium photos are included; locked ones are excluded and listed by public label in `Left out.txt` (labels assigned before exclusion, so numbering is stable). Videos and PDFs never appear.
- **Names:** entries are `publicFileName`-style public labels (`Photo 07.jpg`; Full-res keeps the original's safe extension). Archive `<address>-photos-web-size.zip` / `<address>-photos-full-res.zip`. Never ids, keys or original filenames.
- **Caps:** 300 included photos and 8 GiB of payload, checked from D1 before any R2 call → 422 `zip_too_large {maxPhotos, maxBytes}`. The notice does not count.
- **Re-authorisation:** one D1 statement per check (page enabled, gate open, set number unchanged, asset in that set, photo, `lockedSql = 0`), passed as `authorize` to the writer; null entry (trailer) re-checks page/gate/set. Move the delivery gate SQL out of `lib/delivery-unlock-request.ts` into a shared helper used by both. Any failure aborts the stream (exact Content-Length makes the browser fail the download).
- **Rate limits:** D1 `guest_rate_limits` buckets via `guest/rate-limit.ts` (no KV, no Rate Limiting binding). Per 15 min: zip starts 10/IP + 60/page; prepare 20/IP + 120/page; checks (manifest and zip GET, spent before any R2 HEAD) 60/IP + 300/page. Preparing and refusals never spend a start.
- **Audit:** a fenced `delivery.download_all` row (actor NULL; meta: size, setNumber, count, totalBytes) on each zip start, as the guest Download all does.
- **Methods:** HEAD → 405 and Range → 416 on the zip route, after page admission, with no side effects. Singles keep Range.
- **No migration.**

## Routes (in `delivery/index.ts` `mountDelivery`, raw-path regex, each through `guestRoute`, terminal-route rows added)
- `GET /d/api/pages/:slug/zips/:size` — manifest, read-only, never queues. `{ size, setNumber, photos, totalBytes, tooLarge, leftOut:[{label, reason:"premium_locked"}], archive:{state, pending, retryAfterSeconds?} }`, `state` ∈ ready | preparing | unavailable | too_large.
- `POST /d/api/pages/:slug/zips/:size/prepare` — same-origin JSON (`originRejection`), strict `{}` body; queues missing CRCs, re-enqueues missing Web-size derivatives (`enqueueDeliveryDerivativesSafely`); returns `{state, pending, retryAfterSeconds?}`.
- `GET /d/api/pages/:slug/zips/:size/photos.zip` — order: path → `admitPage` (miss = byte-identical stub) → method/Range → read set (lock settled before R2) → 409 `nothing_to_download` / 422 → check bucket → `assessZip(nativeOnly)` → 409 `download_preparing` + Retry-After / 502 → re-admit, set number unchanged → `planNativeZip` → start buckets → audit → `nativeZipResponse`.
- `size` ∈ `web` | `full`; anything else is the stub (hygienic, like other misses). All responses carry `private, no-store`, `nosniff`, `noindex`, `no-referrer`.
- Shared: `packages/shared/src/client-delivery.ts` gets the size enum, caps, strict manifest/prepare schemas; GLOSSARY gains Web-size, Full-res, Download all.

## Web
- `delivery/delivery-api.ts`: `zipManifest(size)`, `prepareZip(size)`, `zipUrl(size)` (the only place that fetches).
- New `delivery/DeliveryDownloadAll.tsx`: a "Download all" button opening a `reui/dialog` (explicit `sm:max-w-[520px]`), size choice with `reui/radio-group` + `reui/field`/`label` (default Web-size), summary "N photos · X" (`formatBytes`), Left out list (`reui/item`), preparing/ready/timeout via `usePreparedDownload` + `PreparedZipNotice` copy, and a `Download zip` anchor (`reui/button render={<a href download/>}`). Every answer is bound to the dialog's opening and the size it was asked for (lesson "Form lifetime is not component lifetime"); no auto-download; 429 shows cooldown copy; 404 means the page is gone.
- `DeliveryApp.tsx` passes it as `downloadAllSlot` only when the set has at least one unlocked photo; Preview passes nothing. `DeliveryPage.tsx` places the slot on the Photos tab, or the Premium tab when there is no Photos tab.
