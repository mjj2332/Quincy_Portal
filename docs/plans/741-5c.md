## 5b-counts (Codex's shape)
- Extend `videoDtoSchema` with `latestNoteCount: number | null`: `null` when the notes part is off (the aggregate is not run), otherwise an integer >= 0.
- No new endpoint. The upload-completion DTO is built with the same loader, so counts are identical there (Codex trap).
- Counts open root notes on the current Version, both visibilities, under the same rule as the panel's `noteCounts().totals.open`: a tombstone with replies counts, an empty tombstone does not. One grouped query (Codex's SQL).
- After a note write, the Videos list is invalidated alongside the notes list, so counts refresh, including through the existing cross-tab invalidation.
- Card UI: installed `reui/badge` (secondary) shown only when the count is > 0 (deep), text "N open note(s)". Hidden when null.
- Tests: Codex's list, plus the upload-completion DTO.

## 5c-api
- Two routes, preview and commit (POST), share one planner in `workers/app/src/lib/video-note-paste.ts` that calls the shared pure `planPaste` (BigInt middle-moment mapping, half-open ranges, frame offset). Route order: gate 404 → capability 403 → visibility → archived 409, on preview too.
- Input: source note ids (source Version = one Version of the same Video), target Version, optional frame offset. **`visibility` is not accepted** (400 if sent). Visibility and body are copied from the source row in SQL.
- Preview: 200, no writes and no audit. For each note it returns the mapped start and end timecodes, a skip reason (`already_copied`, `out_of_range`, `deleted`, `reply`) and the source revision.
- Commit: sends `{ noteId, revision }` per note. Any source changed since preview → 409 `paste_stale` with a fresh preview, nothing written. The freshness check is fenced inside the same batch (Codex: the SQL fence plus the audit-insert guard). Rows are inserted with `INSERT … ON CONFLICT DO NOTHING`, matching the partial index's WHERE exactly. **One audit row per commit, including all-skipped** (spec 44i; Codex), with copied/skipped counts by reason.
- Limit **100 notes** per operation (Codex), 400 above it.
- A copy references its immediate source and keeps the original credit: original author name and role carry through from a copy of a copy. Duplicate check covers one step of copy history (deep).
- The commit is idempotent: a repeat copies nothing new, so the UI may offer "Try again" after a network failure.
- If D1 rejects `changes()` in the audit statement, use deep's fallback count.

## 5c-ui
- Notes panel header gets a ⋯ (quincy/menu) with "Copy shown notes". On another Version of the same Video, the same menu offers "Paste N notes from vX…", which opens a registry dialog with a table of old → new timecodes, a checkbox per note, skipped notes listed with their reason, and a frame-offset input (`@reui/number-field`, install it through the sandbox per docs/reui-reuse.md). Ticking happens in the dialog, not the list (flag in the PR).
- Clipboard, offset and ticks live in the form store (form lifetime lesson). Closing the dialog loses nothing.
- Each thread shows "Copied from vX · originally by {name}" in VideoNoteThread.
- **Escape fix:** the viewer's open-layer check excludes modal dialogs (`OPEN_POPUP` in project-sheet-layers.ts). Extract `hasOpenModalAbove` and write a red-first test, so Escape in the paste dialog closes only the dialog.
- 409 paste_stale → the dialog refreshes its preview with a notice.
