# #819 Deep link to a video and Version (staff) — settled plan

Synthesised from blind Opus and Codex plans (2026-10-12). Owner chose: video + Version, staff only.

## Decisions
- **Spelling:** `/projects/<projectId>?tab=video&video=<uuid>[&version=<N>]`. Composes with the existing `?tab=video`. Strict canonical order `tab, video, version` (the repo's closed-query rule; the app only ever writes this order). `version`: `^[1-9][0-9]{0,5}$`; video: canonical lowercase UUID. Reject (not-found, like every other malformed staff query): other order, duplicates, trailing `&`, `version` without `video`, `video` with any other tab or `whiteboard`, bare `?video=`. Do not route through `parseDashboardQuery`. Every existing `staffPathFor` output stays byte-identical (`?tab=video`, frozen `?collaboration=open`, `?whiteboard=open`); `projectNotificationRoute` / stored `deep_link_path` untouched.
- **Version identity:** number in the URL (readable; `version_high_water` means never reused), asset id internally. Omitted `version` = current Version. The app always writes an explicit `version`, so a copied link names a fixed cut.
- **History:** `replace` for open, close, Version switch and fallback (Codex). Matches Workspace tab sync, adds no sheet depth, and keeps the existing self-write suppression valid (a push bumps the navigation epoch — Opus' trap). Back/Forward still render whatever selection the entry holds. If, after implementation, a replace still trips arrival-tab focus (focus leaving the dialog), add the one-shot self-write ref Opus describes — don't guess, test it.
- **Router:** in `lib/app-router.tsx`, add `syncProjectVideo(projectId, selection | null)` via `locationStore().replace` with a current-location check against stale callbacks. `ProjectLeaf` passes the route's video selection and the callback. Leaving the Video tab drops `video=` (existing `syncProjectTab` behaviour). Never `useNavigate`/`<Link>`/`router.navigate` (`routing-transport.guard.test.ts`; lessons "A router that owns the URL will canonicalise it").
- **Panel:** `VideoCollectionPanel` derives the open video from the route selection when the prop is present (no second copy in a store — lessons #217 "A copy of URL state in a store…"); keeps `useState` only when absent (harness/other callers). Keep the frozen Viewer-identity ref so the lazy viewer never remounts on a URL write. Card open → `sync(videoId, newest version)`; close → `sync(null)`. Normalise only after a successful list read: missing/trashed/cross-project video → strip to `?tab=video`; loading or failed read never strips.
- **Viewer** (`VideoReviewViewer.tsx`, minimal edits — #818's Download lives in the same header): optional `deepLink?: { version?: number; href(version): string; onVersionShown(version): void }`. Initial asset = URL Version if present in `video.versions`, else `currentAssetId`. Report the shown Version when it differs (this also rewrites a missing Version to the one shown). External change of the URL Version while open re-seeds once. Compare: report side A; no pair/offset in the URL.
- **Copy link:** existing `components/video/CopyTextButton.tsx` in the header; order **Version group · Copy link · Download · Compare**. Absolute URL `new URL(staffPathFor(...), location.origin).href` (as `CopyProjectLinkButton.tsx`). Visible at 390, 44px touch target; hidden while comparing only if Download is (keep consistent with #818).
- **Arrival focus:** `ProjectWorkspace` arrival-focus effect must not pull focus out of an open modal (`hasOpenModalAbove`, `project-sheet-layers.ts`). Cold-link close returns focus to that film's card open control by `data-testid`, else the Trash button.
- **Sign-in:** existing `safeStaffDestination` keeps the full path+query; add tests only.
- **Flag:** none — the panel already sits behind the video review gate; external editors see Copy link only where they see the viewer.
- **No API/schema change.** No Hono route, MCP allowlist, terminal-route or route-manifest change.
