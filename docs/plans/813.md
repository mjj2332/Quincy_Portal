# #813 — accept H.264 video in `.mov` as well as `.mp4` (settled)

Owner decisions: accept `.mov`; treat it as `.mp4` for storage, playback and download names; bytes unchanged, no remux;
no PCM-audio warning; ProRes and HEVC `.mov` still rejected with the existing plain copy.

## Plan

1. **Shared**
   - `packages/shared/src/video-upload.ts`: the reserve schema accepts `/\.(mp4|mov)$/i`; the rejection copy names "MP4 or MOV".
     `normalizeVideoUploadFilename()` replaces a terminal `.mov` (any case) with `.mp4` and leaves `.mp4` names alone.
     `VIDEO_UPLOAD_DECLARED_CONTENT_TYPES` lists what a browser may declare; `VIDEO_UPLOAD_CONTENT_TYPE` stays the stored type.
   - `packages/shared/src/video-mp4-probe.ts`: the opening-box gate admits `ftyp`, `wide`, `mdat` and `moov` (legacy QuickTime); anything
     else stays `not_mp4`. Only that gate relaxes: bounds, `avc1`/`avc3` + `avcC`, HEVC/ProRes rejection, CFR, edit-list, transform and
     fragmentation rules, moov-after-mdat `not_fast_start` and `tmcd` reads are unchanged. A `qt  ` brand passes; PCM audio passes with no warning.
   - `packages/shared/src/testing/mp4-builder.ts`: `ftyp` brand (or `false`), `leading` boxes, `audioCodec`; chunk and timecode offsets
     are computed from the real prefix.
2. **Worker** (`workers/app/src/routes/video-uploads.ts`): reserve accepts a declared `video/mp4` or `video/quicktime` (others keep 415) and
   stores the normalized filename. Stored type stays `video/mp4`, object key `original.mp4`; completion still probes the ETag-pinned bytes
   server-side, so a forged client probe cannot admit HEVC or ProRes. No schema or migration change. Stream headers and guest/delivery
   download names are unchanged; tests prove a QuickTime-bytes upload streams and downloads as `.mp4`.
3. **Web**
   - `lib/video-upload.ts`: `checkVideoFile` accepts `.mov`/`.MOV`; `defaultFilmTitle` strips either extension; the fast-start caution no
     longer says "MP4"; the request MIME stays `video/mp4` whatever type the browser reports.
   - `VideoCard.tsx`: `VIDEO_ACCEPT = ".mp4,.mov,video/mp4,video/quicktime"`.
   - `NewFilmUploader.tsx`, `VideoCollectionPanel.tsx`: copy says H.264 MP4 or MOV.
4. **Tests:** shared probe and schema tests; web `video-upload` and `VideoCollectionPanel` DOM tests; worker `video-upload`, `video-stream`
   and `guest-download` tests.
5. **Docs:** ADR 0020 gains decision 5 (accepted QuickTime containers, unchanged bytes, canonical `.mp4` naming, no PCM warning).
