TB4 domain transaction / single-producer evidence — final state (2026-08-26)

The TB4 contract suite (test/tb4-contracts.test.ts, 16 tests) plus the migration test pass against
the final (post-fix) code. Domain and producer assertions 1–5 prove:

  1. 0031 is additive and contains the literal plan tables, constraints, and named indexes.
  2. Create/edit/delete construct activity before their mutation batch. Create and edit use the
      ordered `INSERT ... SELECT ... WHERE changes() = 1` audit pattern (their preceding INSERT/UPDATE
      statement always affects exactly one row). Delete's own audit guard is also
      `WHERE changes() = 1` — **this SQL-level `changes()` function call does not include
      cascade-deleted rows** (an isolated empirical test against this repo's real D1/Miniflare
      runtime confirmed it returns exactly 1 for a comment-with-mentions delete, matching
      documented SQLite C-API semantics: foreign-key actions are excluded from the SQL `changes()`
      function). Delete's own outer success check is different and intentionally NOT `= 1`: it uses
      `(results[0]?.meta.changes ?? 0) < 1`, because the JS-level `.meta.changes` field returned by
      D1's `run()`/`batch()` on the DELETE statement itself DOES include cascade-deleted
      `project_comment_mentions` rows (the same empirical test observed `.meta.changes === 3` for
      one comment plus two mentions) — an original round-1 fix mistakenly changed the SQL-level
      audit guard to `>= 1` too on the same (partially incorrect) reasoning; Sol round 2 caught
      this and it was reverted back to `= 1`, since only the JS-level field needed the wider check.
      Create order is comment, mention mappings, marker, audit, then outbox/ledger statements.
  3. Payloads carry the immutable activity, false targeted flag, and only admin or sorted
      membership-row occurrence snapshots; no comment/contact fields are persisted in the payload.
      A non-self mention whose recipient has no eligible admin/membership snapshot at occurrence
      time no longer silently skips its outbox row (Sol round 1 fix) — it gets an empty-membership
      snapshot that deterministically fails delivery-time reauthorization instead, preserving the
      plan's "one outbox insert per non-self mapping" invariant.
  4. Project-comment routes contain no direct notifyMentions call; Notice Board calls the narrowed
      notifyNoticeBoardMentions helper.
  5. Queue publication is waitUntil-scheduled after the service batch; accepted sends advance
      pending/queued rows, while rejected sends preserve recoverable intent and record a bounded
      publication error.

The existing project-comments Worker assertions remain in workers/app/test/project-comments.test.ts
and the Notice Board/direct-producer regression assertions remain in the existing Notice Board and
