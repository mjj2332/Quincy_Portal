# #741 slices 6a, 6b-api, 6b-ui — settled plan (freehand markup on video notes)

Sources: 741-6-deep.md (deep-reasoner) and 741-6-codex.md (Codex), written blind to each other. This file wins where they differ.

## Agreed
- **No migration.** 0068 has `drawing_frame`, note revisions and `video_note_markup` (CHECK on 524,288 bytes, cascade-deleted).
- **Three PRs:** 6a extraction → 6b-api → 6b-ui. 6b-ui starts after #756 (5c-ui) merges, because both edit `video-note-form-store.ts`.
- **6a is a pure extraction.**
  - Move the stroke schema to `packages/shared/src/freehand-strokes.ts` in its current loose form; the MCP strict variant stays at its call site. Extract `useFreehandMarkup` and the SVG stroke renderers from `Lightbox.tsx`.
  - Keep the photo cap of 2,000,000 bytes and every photo behaviour, including discarding strokes on Escape.
  - Write the deep plan's 8 characterisation tests and see them green on main **before** moving any code. Every existing Lightbox and annotation test stays green. The browser pass compares the result with main.
- **Data shape.** Video markup uses the same `{x,y}` + colour + width format as photo annotations.
  - Coordinates are fractions of the upright displayed picture: after rotation, excluding letterbox bands, using `usePictureBox`. Width is in CSS pixels. Render as SVG with no DPR scaling.
  - Video envelopes are strict. Colours are hex only, and there must be at least one stroke.
  - Check the size in bytes before the batch: 413 above 524,288, so the database CHECK never surfaces as a 500.
- **Reads are lazy.** The note list keeps `hasMarkup` + `drawingFrame`. Add `GET …/video-notes/:noteId/markup` → `{ noteId, revision, markup | null }`, `private, no-store`. Cache it per note and revision.
- **Revision.** Every markup change bumps the note's revision once and needs `expectedRevision`. This keys the cache, routes races into the existing 409 `note_conflict`, and keeps the paste freshness fence covering markup. A byte-identical change is a no-op.
- **Drawing frame and root notes.** Markup is allowed on root notes only. The drawing frame must equal a point note's `startFrame`, or fall inside a range note's `[start, end)`. Enforce this in the route and repeat it in the batch SQL. Keep `markup_locks_frames`.
- **Text is still required.** A note always needs a body, so a drawing alone can't be posted. This keeps the schema as it is; I decided it here rather than leave it open for the owner, and the PR flags it.
- **Route order:** gate (`notes`, plus `markup` whenever the request touches markup) → capability (`viewVideo` to read, `annotateVideo` to write) → visibility → archived (staff get 409, External gets a concealed 404). Plain note CRUD keeps working when markup is off.
- **Escape.** The first Escape leaves draw mode and keeps the strokes. This differs from the Lightbox, which discards them; the PR flags it. Escape order: inner layers → cancel confirmation or leave draw mode → dirty-form Escape → viewer.
- **Draft state** lives in the form store: composer markup, the frozen drawing frame, the edit baseline and revision, the draw phase, the op id and pen settings. Only the stroke being drawn lives in the hook. Entering draw mode pauses the player and confirms the frame; Post confirms that frame again (story 31).
- **Video traps (Codex §7 table, adopted as written).**
  - While drawing: transport, seeks, marks and J/K/L/Space/arrows/I/O are locked, and held-K is cleared.
  - The overlay only intercepts input over the picture. Strokes stop at the letterbox bands; resize reprojects them.
  - One primary pointer with capture. `touch-action:none` applies only while drawing.
  - Undo removes a whole stroke (Cmd/Ctrl+Z outside text fields).
- **Display.** A selected note's drawing shows only while paused on its frame and while the note is live and filter-visible.
- **Ledger.** The surface is Quincy-owned `FreehandMarkup`. ReUI `signature-pad` was rejected because it stores pixel coordinates, uses variable ink and keeps its own undo. The toolbar uses `reui/toggle`, `toggle-group`, `button`, `tooltip` and `kbd`.

## Where the two plans differed (decisions)
- **Markup removal:** remove a drawing with PATCH `markup: null` and `expectedRevision` (deep). No separate DELETE route.
- **Audit:** one row per mutation (deep). `video_note.create` / `video_note.edit` carry `meta.markup: "add" | "replace" | "remove"`, the stroke count, the byte count and the drawing frame. A note delete adds `hadMarkup`. Strokes and text never go into audit rows.
- **Paste (44f):** paste always carries the mapped drawing frame and copies the markup rows with `INSERT … SELECT`, after the paste audit statement (which reads `changes()` from the note insert). The audit meta counts copies by joining the landed ids. Markup is **not** gated on the paste path: paste only copies existing stored data and returns no stroke content. The `withMarkup` hint (Codex) is dropped.
- **Skip reason:** `drawing_outside` is a skip reason of its own, so 5c-ui (#756, or a follow-up if it has already merged) needs a label for it: "Drawing would fall outside the note".
