## 2. Token, session, passcode model (implemented in 12a, used by 11a)
- **Opaque tokens:** lift `randomToken`/`hashToken` from `external-uploads.ts` into `workers/app/src/lib/opaque-token.ts` (32 random bytes base64url, SHA-256 hex; no behaviour change, and external-uploads re-imports it). Link token and session token both use it. The DB stores only the hash. A 256-bit random token needs no slow hash or pepper, and no new Worker secret.
- **URL:** `${APP_ORIGIN}/d/review#t=<token>`. The fragment never reaches the server, logs, referrers or analytics. The page reads it, then scrubs it at once with `history.replaceState(null, "", "/d/review")` **before any fetch or render** (a bare call in `apps/web/src/guest/link-fragment.ts`; `locationStore` cannot be used because `safeStaffDestination` rewrites `/d/*` to `/`).
- **Exchange:** `POST /d/api/session {token, passcode?}`.
  - On success: `INSERT guest_sessions` (generation = the link's current one, `expires_at = min(now+7d, link.expires_at)`) plus the audit row, in one batch; then `Set-Cookie`.
  - Unknown, expired, revoked or non-pilot token: the stub 404.
  - Passcode needed and absent: `401 {error:"passcode_required"}`. Wrong passcode: `401 {error:"passcode_incorrect"}`. Over the limit: `429 {error:"too_many_attempts", retryAfterSeconds}`.
  - No session row exists before the passcode is accepted. The page keeps the token in memory only (never storage) until then.
- **Cookie:** `__Secure-quincy_guest=<session token>; Path=/d/api; HttpOnly; Secure; SameSite=Strict; Max-Age=<floor((expires_at-now)/1000)>`.
  - `__Host-` is impossible because it forces `Path=/`.
  - `SameSite=Strict` is fine: every guest request is a same-origin fetch, or a `<video src>` from the same-origin page.
  - Logout (`DELETE /d/api/session`) deletes the row and sends `Max-Age=0`.
  - One session per browser: opening a second link replaces the cookie. That's accepted for v1; it's stated in the page copy ("This browser is now reviewing <link label>").
- **Every session-bound request** does one statement: session by `token_hash` JOIN link, requiring `s.expires_at>now`, `l.kind='video_review'`, `l.revoked_at IS NULL`, `l.expires_at>now` and `s.link_generation=l.token_generation`. Then `readVideoReviewGate(db, l.project_id)` must be open with `guest` on. Any failure is the stub 404. `last_seen_at` is written only when older than 5 minutes, so a range request is not a write.
- **Revoke** = one batch: `UPDATE client_links SET revoked_at, revoked_by, updated_at WHERE id=? AND revoked_at IS NULL` + `DELETE FROM guest_sessions WHERE link_id=?` + audit. **Replace link** = one batch: new `token_hash`, `token_generation+1`, delete sessions, audit. The new token is returned once. The generation join closes the exchange-in-flight race that the delete alone leaves open.
- **Passcode:**
  - Staff set 6–64 characters (trimmed; any text).
  - Stored as `pbkdf2-sha256$100000$<salt b64>$<hash b64>` via `crypto.subtle`, with a 16-byte salt per row. 100k is the Workers PBKDF2 ceiling, and it needs no new secret.
  - Compared in constant time.
  - Attempts go through `guest_rate_limits`. The buckets are `passcode:link:<id>` (20 per 15 min) and `passcode:ip:<sha256(ip|window)>` (10 per 15 min). The IP is never stored raw, and rows are swept after 24 h.
  - Reserve-then-check in **one statement**: `INSERT INTO guest_rate_limits(bucket,window_start,count) VALUES(?,?,1) ON CONFLICT(bucket,window_start) DO UPDATE SET count=count+1 WHERE count < ?limit RETURNING count`. No row back means limited.
  - `exchange:ip` (60 per 15 min) also applies to tokenless guessing.
- **Hygiene headers** on `/d/review` and every `/d/api/*` response: `Referrer-Policy: no-referrer`, `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: frame-ancestors 'none'` (on the HTML). No token in any query string. Request bodies are never logged (the guest handlers have no `console.*` taking the body). The 11a create/replace responses are `no-store`.
- **Sweep** (background `0 * * * *` cron, `workers/background/src/index.ts`): delete expired `guest_sessions` and `guest_rate_limits` older than 24 h (expired codes join in 13).

## 5. Slice 12a — guest API surface (`workers/app/src/guest/`; mounted in `index.ts` **before** the `/d/*` fallback, which stays as the unmatched 404)
- **Mount:** `const guest = new Hono<GuestEnv>()`. No `requireSession`, no `getAuth`, no import of `middleware/session` or `auth` (guard test: an import scan over `src/guest/**`). Every route is a `terminalRoute`.
- **Route manifest:** add a class `guest-link` to `SecurityRouteClass`, with contract `{scope:"none", projection:"guest-public" (new value), response:"protocol-404"}`. A manifest test asserts that every `/d/*` registration is either `guest-link` or one of the two fallbacks.
- **Global gate first:** if `video_review` and `video_review_guest` aren't both on (one `feature_flags` read; pilot scope is unknowable before the token), every `/d/*` path returns `c.notFound()`, which is **byte-identical** to today. The test compares status, headers and body against the stub for `/d`, `/d/review`, `/d/api/session` and `/d/api/x`. The per-Project pilot check happens after the session resolves, and failing it is also `c.notFound()`.
- **Origin check (own helper, `guest/origin.ts`):** `POST/PUT/PATCH/DELETE` need `Origin === APP_ORIGIN` plus `content-type: application/json`, else 403 `{error:"invalid_origin"}`. It runs after the global gate. The staff `requireAppOrigin` is not reused, because it's mounted on `/api` only.
- **Staff/guest separation, by construction plus two negative tests:**
  - A valid staff better-auth cookie with no guest cookie on `/d/api/videos` gives the stub 404.
  - A valid guest cookie on `/api/projects/:id/videos` and `/media/video/:id` gives 401.
  - The cookie's `Path=/d/api` means browsers never send it elsewhere anyway.
- **Routes:**
| Route | Behaviour |
|---|---|
| `GET /d/review` | Global gate on and `?link=<uuid>` well-formed (live or not): `c.env.ASSETS.fetch(new Request(new URL("/", c.req.url)))`, re-wrapped with §2's headers (the Worker answers first, so `_headers` never applies). Off: stub. |

- Membership and grants keep history with `removed_at`/`revoked_at` and partial-unique live rows. Re-adding inserts a new row.
- A member Video always has at least one live grant (422 otherwise). Guests never see a member with zero grants.
- Every no-access outcome on `/d/*` is the byte-identical stub 404. The page shows one "unavailable" message.
