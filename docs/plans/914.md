# #914 Project header revamp: settled plan

Synthesised by the session from two blind plans (Opus deep-reasoner and Codex), 2026-10-18.
The base is the Opus plan below; the "Settled decisions" and "Added from the Codex plan" sections override it where they differ.
Prototype: `design/prototypes/project-header-revamp/project-header.html`, frames D1–D6, T1, M1–M6 (A1 not built).

## Settled decisions (owner, 2026-10-18)

- **M5 Deadline view (phone):** native `<input type="date">` / `type="time">` (through `reui/input`, scoped phone presentation) feeding the *same* Deadline draft, version, conflict, reminder and timezone logic. Fields and rules are unchanged; only the phone presentation differs. Save and Clear are pinned at the bottom, above the safe area.
- **Deadline tone:** keep the existing warning window (caution under 72h, as in D1's "2d"), critical once overdue, and add a timezone-correct "Today" label on the due day.
- **Social overlays (#870):** a "Social overlays" section in Project info after Team (desktop), and a row in the phone Status group, behind the same Video review gate as today.
- **Breakpoint:** one query, `(width < 721px)`, exported from ProjectSheet. It is what the sheet's `max-[721px]:` compiles to. Header and sheet never disagree. Verify at 720/721/722.
- **Close (phone):** the header claims the sheet's Close (ref-counted claim on the ProjectSheet context), not a router media query. Loading, error and collaboration-only states keep the sheet's own Close.
- **Desktop Project info "Change" / "Manage":** expand inline in the section; never reopen a header popover under the scrim.
- **Esc in a pushed phone view:** closes the whole drawer (as the frame does); Back pops the view.
- **Archived Admin:** the ⋯ item and phone action read "Restore or delete" (#455 rule kept).
- **Drawer:** none exists in ReUI; install the shadcn base-nova `drawer` (Base UI 1.7.0 Drawer) as `components/reui/drawer.tsx` through the sandbox (docs/reui-reuse.md), with additive, noted edits (`container`, overlay `forceRender`).
- **"Last sync · files"** in the prototype is not in ProjectDetail: omit it. No API change.
- **Avatar stack:** the prototype wants three faces then +N. Add an additive option to `quincy/AvatarStack`, leaving existing callers unchanged.
- **Targets:** keep 44px coarse-pointer hit areas where the prototype draws 40px. Sizes with no token are expressed in tokens; list any leftovers in the PR rather than hard-coding them.
- **Overlays:** keep the installed square list popups (#550 guards) where the prototype draws rounded ones.

## Added from the Codex plan

## 4. Risks, traps, and open decisions
- **Sticky is bounded by its parent.** Row B and the phone tabs can only stick if their parent spans the whole scroll content. Inside `<section aria-label=…>` they scroll away with it. Render Row A as the labelled section, then Row B (and the phone slim bar and tabs) as siblings under `main.work`. Their wrapper `div.contents` is `display: contents`, so the box parent is `main.work`. Or keep everything in the section and make the section `display: contents`, but that risks losing the landmark in Safari; avoid it.
- **Condensing must not shift layout.** Growing Row B from 44px to 60px when condensed pushes the grid down: `overflow-anchor: none` is set on the body, so there is no scroll compensation. Grow it with a matching negative `margin-block-start` so its flow height stays the same. The IntersectionObserver watches Row A (root = sheet body, threshold 0) and never watches Row B, to avoid a feedback loop. Guard with `typeof IntersectionObserver`, since jsdom has none.
- **Phone slim bar.** `position: sticky; top: 0; height: 48px; margin-block-end: -48px` before the project bar, `inert` and `opacity-0` until the project bar has scrolled under. Tabs are `sticky top-[48px]`. Motion is `transition-opacity duration-200 ease-[var(--ease-…)] motion-reduce:transition-none`. Never use `duration-*` without a transition property (lessons § "`duration-*` without a `transition-*` property…", #879 r8). Check safe-area top on the Simulator.
- **Docking Project info.** `SheetContent` is `fixed`, and the Project sheet popup must create no containing block (ProjectSheet header comment), so a fixed child docks to the window, not the sheet. Portal it into the sheet's overlay slot (`container`), make it `absolute`, and give the overlay `absolute inset-0` with z above Close's `z-[30]`. Set width through the variant: `data-[side=right]:w-[440px]` (lessons § "A plain width on a SheetContent loses to the sheet's data-side width", `sheet-width.guard`). Nested Root means no backdrop unless `forceRender` (lessons § "The Project sheet: four traps"). Apply the same to the drawer. Add `focus-visible:!outline-none` if initialFocus lands on the popup (`container-focus.guard`).
- **Esc order.** `hasOpenInnerLayer`'s OPEN_POPUP happens to match a Base UI dialog popup in the slot (no `aria-modal`). Pin that with a test rather than rely on it (lessons § "Escape needs an order", #741 5b). Focus return should follow `ReviewActionSheet`: focus the opener synchronously in `onOpenChange(false)`, because the outer dialog reclaims homeless focus a frame later (#669).
- **Keyboard (M6).** `useVisualViewport` writes `height` and `transform` on its root. Base UI Drawer owns `transform` for swipe, so give the hook a wrapper around the drawer viewport, never `Drawer.Popup`. Use one mechanism: do not also turn on `Drawer.VirtualKeyboardProvider` (lessons § "A layout switched by two flags will disagree"). Focus the Team search synchronously in the push handler with `flushSync`, or iOS raises no keyboard (lessons § "A phone field outside the composer…", #879 3b).
- **#455 latch.** Project info renders inside ProjectHeader's tree, so it reads the same `archived`. The focus-after-flip refs must point to whichever surface is mounted. Popovers and views close on the read-only edge (layout effect), as today.
- **Routing.** No `useNavigate` or `<Link>`. Close goes through `ProjectSheet` context `close()`. Edit details and Show in go through `InternalLink` (`routing-transport.guard`). Tests use a canonical UUID, or InternalLink is not intercepted (project-sheet map).
- **Guards.** `ui-primitive-ratchet` (no raw `<button>` or `role="radio"`: use reui/button, reui/radio-group and reui/item; the ProjectHeaderDropbox and ProjectTeamCombobox allowlist counts may only shrink), `design-system-guards`, `overlay-stacking.guard`, and `shell-breakpoint.guard` (app.css is a shell file: no 771 or 1007 literal).
- **Decisions for the owner. The spec does not settle these; recommendations follow each.**
  - (a) **Social overlays (#870) are not in any frame.** Recommend a "Social overlays" section in Project info after Team (desktop) and a row in the phone Status group, shown only while the Video review gate is open.
  - (b) **M5 draws native date and time pickers, but the reused form is DateTimePopup (calendar plus TimeColumn, with Cancel and Apply in PopupFrame).** The spec forbids changing the Deadline form. Recommend reusing the form inline in its stacked layout (<721px) and treating native pickers as a follow-up. Owner to confirm.
  - (c) **Desktop Project info's "Change" (Deadline) and "Manage" (Team).** Recommend expanding the inline variant in place inside the section, not closing Project info to reopen the header popover under its scrim.
  - (d) **Esc in a pushed phone view.** Recommend it closes the whole drawer, as the frame does; Back pops the view.
  - (e) **Close switch.** Recommend the claim over a router media query (reason in §1).
  - (f) **Archived Admin.** The ⋯ item reads "Restore or delete" (#455 rule kept), and the phone action does the same.
## 5. UI: what each element starts from, and the frame map
- **Starting points:** Project info (desktop): reui/sheet `side="right"`, 440px, docked. Project info (phone): new reui/drawer (base-nova on Base UI Drawer) with a swipe handle. Its rows use the `ReviewActionSheet` chrome (`PHONE_SHEET_CHROME`, `ACTION_ROW`) on reui/item. The Stage view uses reui/radio-group with 52px rows. Tabs: reui/tabs `variant="line"` with reui/badge counts (installed). ⋯: quincy/menu (Base UI, Quincy-owned). Tooltips: reui/tooltip or quincy/IconTip. Team avatars: quincy/AvatarStack (`decorative` inside the named trigger). Buttons: reui/button, outline and ghost, with the icon size and 44px targets. Countdown and states: Badge `*-light` variants. Read-only values: `HEADER_READONLY_VALUE`.
- **Frame map:** D1: HeaderDesktop (Row A section + StatusCluster; Row B WorkspaceTabs). D2: ProjectInfoSheet. D3: ProjectTeamCombobox `presentation="popover"`. D4: ProjectHeaderDeadline chip with the unchanged popover. D5: ProjectMoreMenu, plus Row B `data-header-condensed`. D6: StatusCluster states. T1: HeaderDesktop wrapping via `@container project-header`, actions `ms-auto`. M1: HeaderPhone project bar and sticky tabs. M2: HeaderPhone slim bar. M3: ProjectInfoDrawer info view. M4: Stage view. M5: ProjectDeadlineControl inline view. M6: Team `presentation="inline"` with `useVisualViewport`. A1: not built.
- **Conflicts to raise, not settle:**
  - (i) M5 native pickers versus DateTimePopup (decision b).
  - (ii) D3 search-in-popup versus today's chips-input combobox. The frame needs a new presentation of the same component, so this is not a restyle.
  - (iii) A Tooltip on a reui/select trigger needs a `render` composition. If Base UI fights it, use `title`-free IconTip beside the dot, or the name alone.
  - (iv) The prototype's raw sizes (28px title, 62px or 48px bars, 52px rows, 440px) are expressed in tokens and 44px targets. Any size with no token is listed to the owner rather than hard-coded.
  - (v) The Archived badge and a "Dropbox blocked" warn button have no ReUI equivalent beyond Badge or `Button variant="outline"` with caution tokens. Use those and flag the button tint.
