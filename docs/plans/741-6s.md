# #741 slice 6s — arrow, line, rectangle + redo in the shared markup module (deep-reasoner plan)

Base: worktree `~/quincy-wt/741-6a` @ 3b4fca3c (6a: `lib/use-freehand-markup.ts`, `components/quincy/freehand-strokes.tsx`,
`packages/shared/src/freehand-strokes.ts`). Owner decisions in the brief + the two coordinator addenda are inputs, not reopened.

## 0. Decisions at a glance
1. Wire format: freehand stays **typeless** (bit-identical to every saved annotation); shapes are `{ type: "arrow"|"line"|"rectangle", points: [start, end], color, width }`. No `"freehand"` literal on the wire.
2. Rendering stays SVG in the existing `viewBox="0 0 1 1" preserveAspectRatio="none"` layer. Arrowheads are a polygon computed in **pixel space** from the layer's measured size and converted back to fractions. No `<marker>`.
3. The hook keeps the in-progress item in hook state and commits **by value** on pointer-up. It follows one pointer (by `pointerId`), discards a shape tap below the size threshold, ignores non-finite samples, and adds `onPointerCancel`.
4. History is a pure reference-snapshot module (`past`/`future` of item arrays) that the hook hosts now and the 6b form store can host later. Redo exists, a new draw clears it, and **Clear is undoable** as one step.
5. One shared `components/quincy/MarkupToolbar.tsx` for photo and video, inside the existing floating pill: tool group, then swatches, widths, Undo · Redo · Clear, and a trailing slot. Every control is **always one tap**: no mode swap and no popover.
   - On phones (≤720) a compact form packs two rows: icon-only history and one width-cycle button.
   - On video, before drawing starts, the pill **collapses** to a single "Draw" button.
   - The hint pill and the toolbar share one bottom-anchored stack, so wrapping can never overlap them (§5).
6. No single-letter tool shortcuts (collisions below). Keys are ⌘/Ctrl+Z (undo), ⇧⌘/Ctrl+Shift+Z (redo) and Ctrl+Y (redo, non-Mac only). The host owns the key handling and the toolbar only shows `Kbd` hints.
7. No Shift constraints in 6s (touch can't use them, and they need pixel-space plumbing in `toPoint`). Recorded as a follow-up.
8. Reject Fabric. From FreeFrame, port only the arrowhead angle math and the rect min/abs normalisation (§9).
9. PRs: 6a → **6s-api** → **6s-ui** → 6b-api (can start after 6s-api) → 6b-ui (after 6s-ui and #756).

## 1. Data shape (`packages/shared/src/markup.ts`, renamed from `freehand-strokes.ts` with `git mv`)
- Pieces (loose, as 6a): `strokePointSchema` (unchanged) and `freehandStrokeSchema = strokeSchema.extend({ type: z.never().optional() })`.
  Zod 3.25 omits an absent optional key from the output, so a typeless input stays typeless and keeps its key order (`points,color,width`).
- `shapeSchema = z.object({ type: z.enum(MARKUP_SHAPES), points: z.tuple([pt, pt]), color, width })`, where `MARKUP_SHAPES = ["arrow","line","rectangle"]`.
  Points are stored **as dragged** (start, end), because the arrow's direction needs the order. Rectangles are normalised at render time only, so data written over MCP in either order is drawn the same.
- `markupItemSchema = z.union([shapeSchema, freehandStrokeSchema])`. **The shape schema must come first**: the loose freehand object strips unknown keys and would swallow a 2-point `{type:"line"}` as freehand.
  With `type: z.never().optional()` an unknown `type` (`"circle"`, `"freehand"`) fails **both** branches and returns a 400 on both routes. Extra keys other than `type` are still stripped on the cookie route. The PR flags this change: before, `{type:…}` was silently stripped.
- Keep the export name `strokesSchema = z.array(markupItemSchema).max(STROKE_LIMITS.strokes)`, so `routes/annotations.ts` doesn't change. Types: `FreehandStroke = {points; color; width; type?: undefined}`,
  `MarkupShape`, `MarkupItem = FreehandStroke | MarkupShape`, and `markupKind(item)` → `"freehand"|"arrow"|"line"|"rectangle"`.
- MCP strict variant, composed at its call site as in 6a: `z.union([shapeSchema.extend({points: z.tuple([pt.strict(), pt.strict()])}).strict(), <6a strict freehand, built from strokeSchema with no type key>])`.
  **The strict branch needs no `z.never()`.** A `.strict()` object without a `type` key already refuses `{type:"freehand"|"circle"}`, so `tools/list` never advertises `not:{}`. Only the loose route uses the never trick.
  6b-api builds the video envelope the same way (hex colour, width 1–24, min 1 item) from the same pieces.
- Caps: shapes count toward the existing 200 items, and their 2 points sit far below the 2,000-point cap. Byte caps stay as they are (photo 2,000,000 in the route; video 524,288 in 6b).
  A degenerate shape (both points the same) is **accepted** by the server, since MCP may send one, and the renderer tolerates it. The client never produces one (§3).
- Update the MCP `create_annotation`/`edit_annotation` `.describe()` text and `docs/Guides/MCP.md`: "type omitted = freehand; arrow/line/rectangle take exactly [start, end]".

## 2. Rendering (`components/quincy/markup-layer.tsx`, renamed from `freehand-strokes.tsx`)
- `StrokeVisible` and `StrokeHitTarget` keep their current output for typeless items, attribute for attribute. Characterisation test 2 stays unedited.
- New `MarkupItemVisible({ item, box, opacity, testId })` switches on `markupKind`:
  - **line**: `<line x1 y1 x2 y2>` with `vectorEffect="non-scaling-stroke"`, round cap, `strokeWidth={width}`. This matches freehand's width behaviour.
  - **rectangle**: `<rect x=min y=min width=|dx| height=|dy| fill="none">`, non-scaling stroke, round join. A zero-size rect draws nothing.
  - **arrow**: the shaft is a `<line>` from the start to the head's base centre, and the head is a filled `<polygon>`. Both come from `arrowGeometry(start, end, widthPx, box)` in `packages/shared/src/markup-geometry.ts`.
  - **unknown `type`** (future data or a cached old reader): drawn as a freehand polyline of its points. It never throws and never vanishes.
- `arrowGeometry`, all in px:
  - Endpoints are projected by `box.width/height`, `angle = atan2(dy, dx)`, and the head side length is `L = clamp(3*width + 8, 12, 0.6*shaftLength)`.
  - The head is the apex at `end` plus two base points at `angle ± π/6`, and `shaftEnd = end − L·cos(π/6)·dir`. All points are divided by the box to get back to fractions.
  - It returns `null` when the length is 0 or the box is unknown (0×0). The renderer then draws only the line, and the shape is still visible.
  - Why px: under `preserveAspectRatio="none"` any geometry authored in 0..1 is skewed by the picture's aspect ratio. Markers are worse: `markerUnits="strokeWidth"` reads the width in user units (4 units = 4× the picture width) and ignores non-scaling stroke.
- **Box**: `MarkupLayer` owns the `<svg>` and measures it with a ResizeObserver, using `contentRect`, the layout size before transforms. That is right for the zoomed Lightbox: the CSS zoom transform scales the whole SVG, freehand widths included, and heads must scale with it, not compensate.
  If ResizeObserver is missing (jsdom), it falls back to `offsetWidth/Height`, and 0 means unknown. The outer `<svg>` attributes the Lightbox passes today (class, testid, viewBox, style, handlers) go through unchanged.
- **Hit targets** (Lightbox click-to-select): line and arrow get a transparent `<line>` at width+12 (`pointerEvents: stroke`), plus the head polygon (`pointerEvents: fill`). A rectangle gets a transparent stroke-only `<rect>` at width+12, so an annotation drawn inside a rectangle stays clickable.
- **Tolerant reader** `readStoredMarkup(unknown): MarkupItem[]` (shared): it drops an entry with no usable `points` array and keeps unknown types for the polyline fallback. It replaces the unchecked `result as Stroke[]` in the Lightbox stroke-cache fetch.
  It returns a well-formed input **unchanged** (same objects), so old data cannot drift.

## 3. Interaction (`lib/use-markup.ts`, renamed from `use-freehand-markup.ts`; hook `useMarkup`)
Signature: `useMarkup({ enabled, tool: {kind, color, width}, toPoint, strokes, setStrokes, beforeStart? })` returns
`{ handlers: {onPointerDown, onPointerMove, onPointerUp, onPointerCancel, onPointerLeave}, active, undo, redo, clear, cancel, canUndo, canRedo }`.
- Unchanged from 6a: `preventDefault` + `stopPropagation` before the gate; the sync-or-promise `beforeStart`; pointer capture after the gate; `toPoint` called at pointer time (the live zoomed frame rect).
- Changed from 6a, deliberately (characterisation tests updated with a note in each):
  - **The in-progress item lives in hook state (`active`) and is committed by value on up or leave.** The caller renders `strokes` and then `active`. This is the 6b plan's `commit:"onEnd"`, now the only mode.
  - It gives shapes a live preview with no flicker into the caller's list, and it is what makes exact history possible (§4).
  - **One pointer per gesture:** a second `pointerId` is ignored. Test 6's interleave goes, and the Lightbox gets 6b's `singlePointer`.
  - **A non-finite sample is ignored.** Test 7b's NaN from a 0×0 rect no longer produces a stroke.
- Freehand: down → `[p]`; move appends; up commits. A tap still commits a one-point dot, as pinned by test 2.
- Shapes: down → `{type, points:[p,p]}`; move sets `points[1]`; up commits only if the drag in client px (recorded at down, against `event.clientX/Y` at up) is at least 8 px for line/arrow, or both sides are at least 6 px for a rectangle.
  Otherwise the tap is discarded. `onPointerUp` now receives the event.
- `pointercancel` discards `active`. `pointerleave` commits, which keeps 6a's "leave ends the stroke". Escape mid-gesture: the host calls `cancel()`.
  Endpoints come from `toPoint`'s clamp to [0,1] and 4 dp, so rectangles can't leave the picture.
- Touch: `touch-action:none` stays on the SVG. Annotators already have pinch, pan and swipe off.
- `cloneMarkupItem(item)` (shared) replaces the Edit-drawing preload's inline deep copy. It keeps `type`, and a shape keeps its 2-tuple without a cast.
- Rendering requirement: the caller renders `active` as the **last bare child** with the same `StrokeVisible` / draft testid as a committed draft, with no wrapper `<g>`. That keeps test 2b's inline snapshot and test 5's `draftPolylines` mid-gesture assertion unedited.
- Lightbox wiring:
  - `hasDraftMarkup` adds `markup.active !== null`, so arrows and review keys stay inert during a first stroke.
  - `exitDrawMode` and the asset-change reset call `markup.cancel()`.
  - The `tool` state becomes `{kind:"freehand", color, width}` and persists across assets, as colour and width do today.

## 4. Undo / redo (`lib/markup-history.ts`, pure; hosted by `useMarkup` via `useState`)
- State `{ anchor, past: Item[][], future: Item[][] }`. It is **valid only while `strokes === anchor`**, compared by reference.
  Any outside `setStrokes` (a save clearing the draft, an Edit-drawing preload, an asset change, Escape discard) breaks that identity, and the history resets lazily. No reset calls are scattered through the Lightbox.
- commit(item): `past.push(strokes)`, `future = []`, `setStrokes(next)` with `anchor = next`. clear(): the same, with `next = []`, so **one undo restores everything that was cleared**.
- undo(): with valid `past`, swap to `past.top` and push the current list onto `future`. With no valid past but a non-empty list (preloaded strokes), it falls back to popping the last item, which matches 6a and is itself redoable.
- redo(): the mirror image. `canUndo = strokes.length > 0 || validPast > 0`; `canRedo = validFuture > 0`. `past` is capped at 100 (structural sharing, so the memory cost is trivial).
- Undo, redo and clear are no-ops while a gesture is active. A new draw empties `future`.
- Keys, in the Lightbox window handler. They run **before** the `hasDraftMarkup` early return, so ⌘Z after a Clear and redo after an undo-all still work. They are skipped in text fields, as today.
  - **Check Shift first**: today's `(meta||ctrl)+z` would treat ⇧⌘Z as undo.
  - Ctrl+Y redoes only when `!metaKey`, because ⌘Y is History in Safari and Chrome on macOS.
- The redo stack alone is **not** a draft: navigating away after an undo-all drops it without a confirm.
- Seam for 6b: the form store can either keep `strokes` and let the hook host the history (this works when the store returns the same array reference, which a test pins), or host `markup-history.ts` itself. The functions are the same in both cases.

## 5. Toolbar (`components/quincy/MarkupToolbar.tsx`, shared): one design for photo and video
**Chosen design: "always-expanded direct controls, compact on phones, collapsed rest state on video only".** Inside the existing floating pill.
Order: `label` · **Tool** (Pen, Arrow, Line, Rectangle) · Pen colour (6 swatches with the selected ring) · Stroke width (3 dots) · Undo · **Redo** · Clear · `trailing`
(Lightbox: Cancel/Save while editing; video: **Done**). Groups are `inline-flex` and never split. The pill wraps whole groups, with `reui/separator` (vertical) between groups at ≥721.

Rejected alternatives:
- **(a) Frame.io/FreeFrame mode swap** (one Draw button, then ‹ back · tools · swatches · undo/redo).
  - On photo it saves nothing while drawing, because the drawing set *is* the full set.
  - A Lightbox annotator is always in draw mode (a drag always draws, pan/zoom is off), so a swap would only add a click before every annotation and change a model the owner kept.
  - Kept **only as video's rest state** (below), where an explicit draw mode already exists (pause + confirm the frame).
- **(b) Popover or dropdown for tools, colours or widths.**
  - It is the only route to one row on a phone: 6 triggers × 44 ≈ 300 px. The cost is that every change takes 2 taps, during a session where switching colour and tool is the main activity.
  - A Base UI popup inside the Lightbox also brings back lessons "Base UI's dialog Esc stopPropagation()s on document…": one Escape could close the popup *and* run `exitDrawMode`, discarding the drawing. Avoidable, but the risk isn't worth a row.

**Widths** (28 px targets at ≥721; Lightbox desktop stage = 1280 − 380 = 900, pill max = 868):

- **1280, Edit drawing**: Cancel/Save add about 150, so **two rows**, with Cancel/Save wrapping together.
  - The compare view (450 px stage) wraps today and still does.
  - If the browser pass measures new-markup mode wrapping at 1280, the pre-agreed fallback is icon-only history at ≥721 too. That is not an owner question.
- **Phone 390** (`compact` = Lightbox `band === "phone"`; video uses its own ≤720 flag). 44 px targets, 4 px gaps inside groups, pill padding `--space-2`, inner width 390 − 16 − 16 = 358:

  - **2 rows at 390 and 375, against 3 rows today**, and 3 rows at 360.
  - Flagged as owner-visible: on phones, three dots become one cycle button.
- **Tablets with a coarse pointer** (≥721): 44 px via `min-[721px]:pointer-coarse:` sizing, scoped as in lessons "A touch phone matches `pointer-coarse:` too…". Two rows at 768.

## 9. FreeFrame reuse (MIT, © 2026 Techiebutler)
| Piece | Verdict | Reason |
|---|---|---|
| Fabric.js itself | **Reject** | Fabric 7 is a large lazy chunk (hundreds of KB minified) for 4 shapes. Its pixel-space JSON (`_canvasWidth`, `_frameSpace`) would mean a converter or a dual path for every saved photo annotation, which breaks "bit-for-bit". MCP's strict schema can't meaningfully describe Fabric JSON. A canvas raster loses DOM hit-testing, which Lightbox click-to-select uses. Its module-level `sharedFabric`/`sharedHistory` is exactly lessons "A module-singleton store outlives whatever mounted it" (#217), and FreeFrame's own "inactive pane never attaches the shared drawing" tests are patches over it. |
| Shape drag lifecycle (down creates a zero-size shape, move updates, up finalises) | **Port the logic** | The same three phases, rewritten for pointer events. Fixed along the way: the `await import()` in mousedown (a race with early moves), no minimum-size discard, the hard-coded `strokeWidth: 2` that ignores the brush, and no cancel handling. |
| Arrowhead geometry (`atan2`, ±π/6, apex at the end point) | **Port the logic** | Done in px from the measured box, with the length scaled by width instead of a fixed 12 px, and the shaft shortened under the head. The head is **part of the arrow item**, so one undo removes the whole arrow; FreeFrame's separate polygon splits it. `markup-geometry.ts` carries the MIT notice. |
| Rect normalisation (`min`/`abs`) | **Port the logic** | Applied at render time (§2). The notice is in the same geometry module if the helper lives there. |
| Overlay scaling (`scaleX/scaleY` from the stored canvas size, legacy `containBox`) | **Reject** | It scales stroke widths non-uniformly and needs size metadata. Our picture-box fractions with non-scaling stroke already solve it, and the letterbox-reconstruction branch is the bug class our model avoids. |
| Undo (whole-canvas JSON snapshots, max 20, no redo, Clear wipes the history) | **Reject** | Replaced by the reference-snapshot history in §4. |
| Toolbar (`comment-input.tsx`) and its draw-mode content swap | **Reject the layout** (owner); **take the tool order** pen, arrow, line, rectangle. The swap pattern is kept only as video's collapsed rest state (§5) | Its buttons are 28 px, `title`-only (no `aria-label`/`aria-pressed`), and it uses a `MousePointer` icon for Arrow. Quincy uses the ReUI parts in §5. |
| `review-store` pen fields (tool, colour, size) | **Port the shape only** | It's already ours (`tool` state; 6b's form store). Its global zustand drawing state is rejected for the same singleton reason. |
| Tests | **Reject** | Nothing about geometry or drawing to port (store setters, comment submit). We keep the *idea* of the cross-pane leak test as "two hook instances share no state". |
No FreeFrame stack, permission model or UI markup is copied. Only `markup-geometry.ts` contains ported logic and needs the notice.
