| Legacy tables | `publishes`, `premium_unlocks` and `client_links.kind='delivery'` stay dormant. Dropping them is non-additive and buys nothing now; a later cleanup issue. The asset-delete guard stops reading `premium_unlocks`. | Codex. |
| Gate | `feature_flags`: `client_delivery` master plus `client_delivery_all_projects` or `client_delivery_pilot:<projectId>`, missing row = off, mirroring `video-review-gate.ts`. Migration seeds nothing. | Deep (repo pattern). |
| Address | Minted once at first Publish from street + suburb (NFKD, lowercase, hyphens, ≤ 60 chars, fallback `property`), plus `-` and **6 chars** from `23456789bcdfghjkmnpqrstvwxz`. Never recomputed. Collision → retry, detected through `error.cause`. | Deep. |
| Publish | One D1 batch: validate selection, Project state and expected latest set; allocate set number (and address on first Publish); insert set + items; on first Publish compose the Delivered stage move from `lib/project-stage.ts` / the `@quincy/db` bundle; audit + outbox; advance pointer. A client **operation id** makes retries idempotent; two different concurrent Publishes → one winner, one 409. First Publish enables the page; re-publishing an off page keeps it off. | Both; op-id from Codex. |
| Preview | `POST /preview` renders the DTO for an unpublished selection; creates nothing; media behind the staff session; "Request unlock" in Preview is local only. | Both. |
| Derivatives | Per-variant spec versions (`RENDITION_VARIANT_SPEC`); `RENDITION_SPEC_VERSION` is **not** bumped (it would regenerate every thumb/web in production). `delivery_web`: JPEG, 2048 px, q85, from the original via the signed `/cdn-cgi/image/` path. `premium_preview`: 1600 px, watermark burned in by the background Images binding over the asset's own `web` rendition (under the 20 MB input cap). Single `generate_renditions` message type, so DLQ/replay are unchanged. Missing preview fails closed (processing tile), never the original. | Deep; JPEG from Codex. |
| Zips | Photos only, reusing `createZipStream` (STORE/ZIP64). Default caps **300 photos / 8 GB** (8 GB matches the approved Review cap), pinned by the spike. HEAD-and-size-check before byte 0; every entry re-authorises (page on, item in current set, still unlocked) and a failure errors the stream. Locked photos excluded and listed in `Left out.txt`. 10/IP and 60/page zip starts per 15 min. Singles keep Range and are not D1-limited. | Both. |
| Request unlock | `POST /d/api/pages/:slug/items/:handle/unlock-request`. Order: resolve → Origin/content-type → item locked (else 409 `not_locked`) → buckets 5/IP/15 min, 30/page/day, **1/item/day**. A full per-item bucket answers 202 `already_requested` and writes nothing. One fenced batch writes audit (actor NULL, IP bucket hash only) + outbox. Recipients: active Admins + the Project's internal Editors; External editors and Photographers never. New type `delivery_unlock_requested` across every notification registry in one slice; external policy **denied**. | Deep; recipients both. |
| Public surface | `GET /d/:slug` shell; `GET /d/api/pages/:slug` strict DTO; item media/stream/download routes; photo zip preflight + stream; unlock-request. Unknown, off, unpublished and gate-shut give the same hygienic 404; a well-formed slug always gets the same shell. Slug matcher: lowercase, contains a hyphen, excludes `review`, `unsubscribe`, `api`; no normalisation of encoded spellings, trailing slashes or extra segments. Lock checked **before** R2 HEAD/Range/conditional handling; locked → 403 `premium_locked` on GET, HEAD and Range alike. DTO exposes random 16-char handles and labels like "Photo 07", never ids, keys, original filenames, staff, agent, invoice or payment data. All responses `noindex`, `no-referrer`, `private, no-store`, `nosniff`. Route order: Review → unsubscribe → Delivery API → slug shell → `/d` stubs → SPA. | Both. |

## Schema (slice 1)

Migration `0071_delivery_schema.sql`. The coordinator approved these seven choices where §1 did not name a table.

1. `delivery_pages` is keyed on `project_id` (no surrogate id); nothing references it. Columns: `slug` (UNIQUE), `enabled`, `latest_set_number`, `created_at`, `updated_at`.
2. The cover lives on `delivery_sets.cover_asset_id` only, because a cover is per Publish. The page reads it through its latest set.
3. `cover_asset_id` is `ON DELETE SET NULL`; the §1 asset-delete guard already refuses deleting an Asset in the current set.
4. The page stores `latest_set_number` (integer), not a set FK, so pages and sets are not circular. `UNIQUE (project_id, set_number)` resolves the set.
5. Slug collisions surface as the UNIQUE error on `delivery_pages_slug_unique` and are retried (via `error.cause`).
6. The Publish operation id is `delivery_sets.operation_id` with `UNIQUE (project_id, operation_id)`. It is a plain idempotency key, registered in `NOT_ENTITY_REFERENCES`.
7. The page row is created at the first Publish, so `latest_set_number` is `NOT NULL >= 1`.

Also: `delivery_set_items` has `PRIMARY KEY (set_id, asset_id)`, `UNIQUE (set_id, handle)` with a 16-character handle, and an index on `asset_id` for the current-set guard. `asset_premium_unlocks` mirrors `video_premium_unlocks`. `assets.delivery_premium` is `integer NOT NULL DEFAULT 0 CHECK (IN (0, 1))`. Every CHECK is single-column.

## 5. Owner questions (each has a default; building proceeds on the default)

1. **Video premium.** The glossary says a Premium Asset "stays premium for good", but #785 shipped a Video premium on/off switch, and `manageVideoPremium` is Admin-only while stories 26–28 have Editors unlocking. *Default: Editors may Unlock Videos; Video premium becomes permanent once a Video is published to a Delivery page (the on/off switch stays for Review-only Videos).*
   *Applied to photos and documents (slice 2): `{premium:false}` is allowed only while the Asset (for a Video, any of its Versions) has never been published to a Delivery page, in any set, current or old (derived from `delivery_set_items`, which nothing deletes except with the Asset or Project); once it has, it answers 409 `premium_published` and access is controlled with Unlock/Re-lock.*
2. **Unlock on re-edit.** *Default: a paid Unlock carries to a re-edited version of the same photo.*
3. **Studio credit and contact email** for the page footer and "Ask the studio". *Default: "Quincy Productions" and a `STUDIO_CONTACT_EMAIL` var the owner sets.* Needed by slice 9.
4. **Watermark artwork.** *Default: a tiled diagonal wordmark at 50% opacity from a PNG the owner supplies.* The spike uses a placeholder; real art is needed before slice 4 merges.
5. **The spike needs a non-production deploy** with an Images binding; `docs/Guides/CI-Deploy.md` has no preview path. *Default: the owner uploads a preview version of the background Worker (`wrangler versions upload`) with the binding added, and runs the spike script the session provides.* If both watermark methods fail, locked premium photos ship as an imageless "Premium extra" tile.
6. **Sizes.** *Defaults: Web-size 2048 px JPEG; zip caps 300 photos / 8 GB.*
