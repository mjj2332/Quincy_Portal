# #828 — film title is always the latest live Version's file name

Settled from the Opus and Codex plans (blind, in parallel). Opus: store and maintain. Codex: derive on read.
**Decision: store `videos.title` and maintain it inside `RECOMPUTE_CURRENT_SQL`.**
Verified choke point: `RECOMPUTE_CURRENT_SQL` runs on every Version-set change — upload completion
(`routes/video-uploads.ts` via `recomputeCurrentStatements`), `removeVersion`, `restoreVersion`, `restoreVideo`
(`lib/video-trash.ts` via `fencedRecompute`). Other `superseded_at` writers are photo/PDF/Dropbox paths, not video.
Purge only deletes removed Versions, never the newest live one, so it needs no hook. Deriving would touch 13–15
reader sites and every future reader would have to remember the rule.

## Rule (SQL is the authority; TS matches it)
`FILM_TITLE_SQL(f)`: SQLite `trim()` (spaces only), drop one trailing `.mp4`/`.mov` (any case), trim, `substr(…,1,200)`
(code points), trim; empty → `'Untitled film'`. `filmTitleFromFilename` in `packages/shared` mirrors it exactly
(spaces only, `Array.from` slicing). Web's `defaultFilmTitle` is deleted in favour of the shared function.
Parity test runs one table through both, including a tab, an NBSP, and an emoji straddling position 200.

## Changes
- `lib/video-live-sql.ts`: add the title UPDATE to `RECOMPUTE_CURRENT_SQL` (`COALESCE(…, title)`, only for live Videos,
  `title IS NOT …` guard, ends in a WHERE so `fencedRecompute`'s audit suffix still applies). Check every caller's
  positional reads of batch `results[...]` (e.g. `video-uploads.ts:278`) stay correct with the extra statement.
- `routes/video-uploads.ts`: v1 reservation stores the server-derived title in `new_video_title` (keeps 0068's CHECK);
  reserve schema ignores a stale client `title` for one release; "new film" = `videoId` absent.
- Web: remove the Film title field from `NewFilmUploader`; tray label from `filmTitleFromFilename(file.name)`;
  POST stops sending `title`.
- Migration `0074_film_title_from_latest_version.sql`: data-only backfill `UPDATE videos SET title = …` for live Videos.
  Idempotent; owner re-runs the same UPDATE after deploy. Migration test + guard that its SQL equals `FILM_TITLE_SQL`.
- Docs: shared GLOSSARY "Video", ADR 0020 note, lessons.md entry.

## Out of scope (fenced)
- Public Delivery page keeps anonymous "Video NN" — derived title is the original filename, which #787 forbids there.
  Staff Delivery candidate names follow `v.title` automatically.
- Already-stored/sent notifications are not re-titled; future ones read `v.title` at send time.
- Guest review page: a link granting only v2 shows the film's current (v4) title — noted in the PR body.

## Tests (red first)
Parity; upload v1 title, v2 retitles, `.mp4`-only name → "Untitled film", reserve without title, stale title ignored;
trash newest → falls back, restore → returns, trash older → unchanged, whole-film removal freezes, restoreVideo refreshes,
refused (fenced) remove leaves title; readers seeded with a stale title (guest read, staff download disposition,
marker export, notification facts); DOM: no Film title field, no `title` in POST, `.MOV` tray label.

## Reuse ledger
Removed: `NewFilmUploader` Film title `QuincyField`. Kept unchanged: `FileDropzone`, `FilePickButton`, `Notice`, `Button`.
No new UI element.
