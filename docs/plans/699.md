# #699 settled plan: Portal MCP for AI clients

Synthesised from two blind passes, Opus (deep-reasoner) and Codex (gpt-6.1-sol), on
`origin/main@7d7590e5`. Spec: `docs/plans/699-spec.md`. ADR: `docs/adr/0019`. Paths are relative
to `portal/`. **W**=`workers/app/src`.

## Where the passes agreed (adopted)

- **OAuth: `@cloudflare/workers-oauth-provider`, mounted inside Hono.** better-auth stays the
  closed Google-only identity provider. Its `mcp` plugin was rejected by both passes: plaintext
  tokens, refresh that never invalidates the old token, one global token lifetime. The
  `oidcProvider` plugin is deprecated, and `@better-auth/oauth-provider` would mean upgrading the
  live auth stack, with an absolute (not idle) refresh lifetime.
  - The library keeps its own state in a new `OAUTH_KV` binding.
  - D1 `mcp_connections` is the Portal's record of authority, checked on **every** `/mcp` call
    and every token exchange: `revoked_at`, the `authorization_epoch` snapshot, last use. KV
    deletion is cleanup, not the revocation boundary.
- **Token rules live in `tokenExchangeCallback`.** Any grant containing `admin` gets a 900 s access
  token with `refreshTokenTTL: 0`. Other grants get a 1 h access token and `refreshTokenIdleTTL`
  of 30 days. A revoked connection or a moved epoch throws `invalid_grant`. `mcp_access` off
  throws `temporarily_unavailable`, which does not revoke.
- **In-process dispatch.** A tool builds a fresh `Request(APP_ORIGIN + "/api/…")` with no
  cookie, Origin or Authorization header, and binds verified claims to *that Request object*.
  Then `app.fetch(req, c.env, c.executionCtx)` runs on the top-level app, so
  `boardSchemaVariant` runs too.
  - `requireSession` and `requireAppOrigin` take the MCP branch only when the bound Request
    `=== c.req.raw`. The MCP branch skips `getSession` and still re-checks active, role and
    epoch.
  - No browser request can reach that branch, and `/api/*` never reads `Authorization`.
  - Never spread or clone `env` (#360, `auth-instance-reuse.test.ts`).
  - A fixed route allowlist plus a tool catalog; no generic request tool.
- **Provenance is carried on the principal.**
  - `SessionUser` and `AuditPrincipal` gain `via`. `auditMeta()` appends
    `{via:"mcp", client}` and rejects a `via` key supplied by the caller.
  - Rename `projects.ts:394` `via:"create"` → `source:"create"`.
  - Fix the raw sites that take a pre-built `metaJson`: `routes/users.ts` (≈97, 227), `admin.ts`
    (≈196), `packages/db/src/{stage-board-bundles,shoot-date-fill}.ts`.
  - The client name comes from consented registration metadata, never from MCP
    `clientInfo`.
- **Comment and activity markers are joined at read time** to the create audit row. No comment
  migration.
- **Signed downloads:** separate secret `MCP_DOWNLOAD_SECRET` and their own route family, not
  `/__transform-source`.
  - Bound to target, user, epoch, connection, and an expiry of at most 15 minutes.
  - Redemption re-checks the grant, then dispatches to the existing `/media/asset/…` or
    zip-ticket route, so the existing authorization and caps apply.
  - Audited at issue and at redemption.
- **Whiteboard:** a thin Hono route calls a typed DO method (`applyServerEdits`) that reuses
  `authorize()`, the generation, archive and purge fences, reconciliation, broadcast and
  snapshotting.
  - Never fake a WebSocket upgrade.
  - The tools take a strict, simplified command schema (text, sticky, shape, arrow, place-media,
    edit, move, delete). The server sets ids, indices and versions.
  - The edit appears as a presence peer "‹user› via ‹client›". There is no restore tool.
- **Scope follows the operation's capability, not its URL.** Admin-only capabilities need the
  `admin` scope even outside `/admin`: `adminBackend` routes under `/projects`, and Project
  delete. Forbidden operations have no catalog entry at all.
- **Provenance must merge before any write tool.**

## Where they diverged, and the call

| Question | Opus | Codex | Decision |
|---|---|---|---|
| Request↔claims binding | `AsyncLocalStorage` | module-private `WeakMap` | **ALS**: precedent in `W/lib/server-timing.ts`; `nodejs_compat` on. Identity check `store.request === c.req.raw` either way. |
| Rate limiter | Workers rate-limit binding per connection | `McpGrantDO` rolling windows | **Binding** (spec says "about"; no new DO class, so ADR 0017's rollback floor is unchanged). Inject it for tests; a DO is the fallback if the account lacks the binding. |
| Project-delete confirm | HMAC confirm token (conn+project+summary hash, 5 min) | challenge stored in the grant DO | **HMAC token**; the writer re-checks the summary hash before deleting. |
| Activity provenance | one `via_client` column filled from the gating audit row | `via` + `client_name` columns | **One column, from the audit row**: one writer (`packages/db/src/project-activity.ts:98`), no call-site changes. |
| Consent handle | library handle (spike to confirm) | D1 `mcp_authorization_requests` | **Spike decides**; fall back to a 10-min D1 row if the handle isn't path-safe or session-bound. |
| First slice | the whole door + `get_me` | foundation only, no tokens issued | **Split**: 1a foundation, 1b door. |

## Tickets (each its own PR, all dark behind `mcp_access`)

0. **Spike (½ day, throwaway):** `workers-oauth-provider` inside Hono. Settle three things:
   how the helpers are obtained, the consent-handle format, and whether `beginConsent` sets a
   cookie. No merge.
1. **1a Foundation.** Migration `0066`: the `mcp_access` flag (seeded 0,
   `ON CONFLICT DO NOTHING`) and `mcp_connections`.
   - Code: `lib/mcp-access.ts`, `lib/mcp-dispatch-context.ts`, `mcp/dispatch.ts`,
     `mcp/route-allowlist.ts`, the session and origin branches, admin `mcp-access` settings
     routes.
   - Red tests:
     - A bearer token to `/api` gives 401; an unsafe request with no Origin gives 403; spoofed
       headers do nothing.
     - An ALS store bound to another Request gives 401.
     - Revoked, deactivated or epoch-bumped connections are refused.
     - Concurrent principals stay isolated.
2. **1b The door.** OAuth endpoints and discovery (`/mcp` and `/mcp/` both registered, so a
   trailing slash can't bypass the gate), DCR, the SPA consent route, Connected apps list and
   revoke, admin revoke-all, the flag switch in Admin, the `get_me` tool.
   - `wrangler.jsonc`: `OAUTH_KV`, `run_worker_first` entries.
   - `staff-routes.ts`: new route kinds; `safeStaffDestination` must admit them.
   - UI follows the reuse ledger below. Two-stage browser pass.
3. **Reads and rate limit.** Projects, my tasks, Stages, assignable people, comments,
   activity, notifications, notice board, annotations, embedded media and link previews,
   Asset metadata, admin reads (under the `read` scope, admin role only).
   - Per-role integration tests, external editors included.
4. **Provenance.** Migration `0067` (`project_activity_events.via_client`), the `auditMeta`
   change, the raw-site fixes, the `source` rename, the UI markers.
   - `test/mcp-audit-parity.test.ts`: every write tool's audit and activity rows carry `via`.
5. **Core writes.** Project create, details, priority, Deadline, Editors, Stage move,
   archive/restore, Subtasks, comments, notification mark-read, Video Collection links.
   - Both 422 confirmation errors are relayed to the client, which retries with
     `confirm: true`.
6. **Collaboration writes.** Annotations, notice board, review/selection, embedded media,
   link previews. No uploads.
7. **Signed downloads.**
8. **Whiteboard read and edit.**
9. **Admin scope.** Consent offers it to admins only, with a warning. Admin writes: Dropbox,
   AutoHDR, replay, retry. Project delete through the confirm token. Background service calls

10. **Close-out.** ADR 0019 → accepted; `docs/Guides/MCP.md`; lessons; production `OAUTH_KV` and

## Risks to watch

- The KV namespace must exist in production before deploy, or the Worker fails to bind.
- The router canonicalises the consent URL (lesson "A router that owns the URL will
  canonicalise it"). Leave with `window.location.assign`.
- A nested `app.fetch` writes into the outer Server-Timing store. Harmless, but assert on it.
- Hono router-wide middleware leaks across sibling mounts. Keep `/mcp` and `/oauth/*` outside
  `/api`.
