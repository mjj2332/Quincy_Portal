## 2. Data shape
- **Stroke:** `{ points: {x,y}[], color, width }` — identical to photo annotations (one shared schema, one renderer). `x,y` are fractions of the
  **displayed picture box** (post-rotation, letterbox excluded), clamped to [0,1], 4 dp. `width` is CSS px with non-scaling stroke (same as the Lightbox:
  a line keeps its on-screen weight at any player size; deliberate, matches photos).
- **Video-only tightening** (schema, not hook): strict objects, hex colour, width 1..24, `strokes.min(1)`; a single-point stroke is drawn as a zero-length
  round-cap polyline in the video renderer variant (the Lightbox's `r = width/600` circle becomes an ellipse in a non-square box with `preserveAspectRatio="none"`;
  leave the Lightbox alone, note it as a follow-up).
- **Size:** server measures `strokesJsonBytes` <= 524288 BEFORE the batch -> 413 `markup_too_large` (never let the CHECK fail into a 500). Schema bounds
  (200 x 2000 points ~ 10 MB) are wider than the byte cap, so bytes decide. Client: the same function blocks Post/Save with an inline Notice, and the hook
  (video only, `minDistance` option, default 0 = Lightbox unchanged) drops points closer than 0.002 of the box to keep long strokes well under the cap.
- **drawingFrame:** the confirmed frame the person drew on. Invariant (same as `planPaste`): point note `drawingFrame === startFrame`; range
  `start <= drawingFrame < end`. Enforced in the route and repeated in the SQL fence of every markup write.
- **Inline vs lazy — pick lazy.** Inline: one request, consistent snapshot, but the list is one unpaged response re-fetched after every write and on
  cross-tab invalidation, and one note may be 512 KiB; ten drawn notes is 5 MB per refetch. Lazy: one GET per selected note, cached in TanStack Query under
  `[videoNoteMarkup, projectId, noteId, revision]` — revision is to video markup what `strokeR2Key` is to photo markup. Cost: a short load on first select (show
  nothing until loaded; never seed an editor with `[]` — the Lightbox `strokesReady` lesson). `Cache-Control: private, no-store` like annotation markup.
- **Every markup write bumps `video_notes.revision` + `edited_at`** and requires `expectedRevision`. That one rule makes the lazy cache key correct, routes markup
  races through the existing 409 conflict path, and keeps the 5c paste fence (`x.revision = expected`) covering markup.
- **Body stays required** (5a `body.min(1)`); a drawing-only note is out of scope. Owner question if they want it (it is a schema change).

## 3. Routes, order, audit
Order for every route: malformed id 400 -> gate 404 (`notes`, and `markup` when the request reads or carries markup; one `readVideoReviewGate` read)
-> capability 403 (`viewVideo` read, `annotateVideo` write) -> visibility (External 404, staff 403) -> archived 409 (External 404) -> note 404 -> author 403 -> deleted 409 -> revision 409 -> validation 422.
1. **Create** `POST .../video-versions/:assetId/notes` with `markup`: 422 `drawing_outside_note` when the invariant fails; 413 on bytes. One batch: audit
   (`video_note.create`, meta `+ markup: { drawingFrame, strokes: n, bytes }`), note INSERT (`drawing_frame = ?`), markup INSERT fenced on `EXISTS audit`, archived snapshot.
2. **Edit** `PATCH .../video-notes/:noteId` with `markup` (object or null): reply -> 422 `reply_has_no_markup`; frames + markup in one request -> 422
   `markup_with_frames` (the UPDATE's markup lock runs before the markup statement, so a combined request cannot be atomic and correct). One batch:
   UPDATE note (`drawing_frame`, revision+1, edited_at; author, revision, not deleted, project fence, drawing-in-range fence; markup counts as a change),
   audit `WHERE changes() = 1`, then `MARKUP_UPSERT_SQL ... ON CONFLICT(note_id) DO UPDATE` or `MARKUP_DELETE_SQL`, each `WHERE EXISTS audit`. Audit action
   stays `video_note.edit` with `changed: ["body"?, "markup"]` and `markup: { op: "add"|"replace"|"remove", strokes, bytes }` (story 41: one row per change, the
   op says what happened). Same-state noop writes nothing, as today. The UPDATE binds `drawing_frame` = new value, NULL on remove, or the head's current
   value when markup is absent from the request.
3. **Delete** unchanged (cascade / tombstone already remove markup); add `hadMarkup` to both delete audits' meta.
4. **Read** `GET .../video-notes/:noteId/markup`: read order above with `viewVideo`; 404 when no markup or tombstone. `readNoteMarkup` takes `publicOnly` so the
   slice-12 guest route reuses it with the internal filter in SQL. Not audited (reads are not).
5. **Paste** (44f): planner reads `drawing_frame` and `has_markup`; copies JSON `{ id, src, start, end, draw }`; `PASTE_INSERT_SQL` sets `drawing_frame = $.draw`;
   NEW statement after `PASTE_AUDIT_SQL` (it must come after: the audit reads `changes()` of the note INSERT):
   `INSERT INTO video_note_markup SELECT t.id, k.strokes_json, now, now FROM json_each(copies) r JOIN video_notes t ON t.id = $.id AND t.asset_id = target
   AND t.copied_from_note_id = $.src JOIN video_note_markup k ON k.note_id = $.src WHERE EXISTS (audit row)`. Fresh copy ids mean only rows this commit inserted
   get markup. Audit meta gains `withMarkup` (counted in the audit statement by joining landed copies to source markup) and `skippedByReason.drawing_outside`.
   Paste copies markup whatever the `markup` part says: it is data preservation, not authoring.
Gate interplay: with `markup` off, the list still reports `hasMarkup` (frames stay locked, which is true), the UI hides draw/edit-drawing and shows "Drawing hidden".

## 4. Where draft state lives (form-lifetime lesson)
In the form store slot, never in components:
- `Composer.markup: { strokes: FreehandStroke[]; drawingFrame: number; clock: object } | null` — the clock-identity rule of `StoredMarks`: strokes made
  on a clock that is gone (Version left and re-opened) are kept but must be re-confirmed (Post seeks and confirms `drawingFrame` anyway).
- `OpenForm.markup: { base: Strokes | null; value: Strokes | null; drawingFrame; touched }` for edit; `save()` sends `markup` only when touched. Once a
  drawing is added in an edit, the form's frame controls lock (`frames` false, marks refused by `takeMark`), so `save()` never sends frames with markup.
- `Slot.draw: { form: "composer" | "edit"; phase: "confirming" | "drawing" } | null` and `Slot.tool { color, width }` (survives remount).
- Each committed stroke, undo and clear bumps the draft `revision` (so a success after "kept drawing" never clears the newer strokes). `isDirty` includes markup.
- Ephemeral: the in-progress gesture only (`commit: "onEnd"` in the hook): committing per pointermove would notify every store subscriber at 120 Hz.
- Commands: `enterDraw(assetId, clock, form)` = pause -> seek to existing `drawingFrame` if any, else the frame on screen (edit path: clamped into the note's
  `[start, end)`, so the fence can never 422 it) -> `awaitConfirmedFrame` (10 s, the `post()` timer and cancellation) -> phase drawing with the frozen frame;
  the overlay (`tabIndex={-1}`) takes focus so ⌘Z and Escape have a target; `addStroke`, `undoStroke`, `clearStrokes` (empty -> markup null), `exitDraw`.
- `post()`: with markup, the frame to seek and confirm is `drawingFrame` (story 31: confirmed before drawing AND before submitting); without marks the note
  becomes a point at `drawingFrame`; with marks that exclude it -> problem "The drawing is on {tc}, outside In/Out" and nothing sent.
- Version change, viewer close, principal change: confirmations cancelled (existing `cancelAll`/`leave`), draw phase ends, strokes kept in the slot.

## 5. Video-specific traps
- **Drawing while paused:** draw phase exists only after the confirmation; during it `transportLocked` disables Play/step/scrubber and the player's
  `handleKeyDown` returns false, so nothing can move the frame under the pen. Leaving draw mode unlocks; the overlay then shows the draft only while
  `clock.frame === drawingFrame && !playing`, with a "Drawing on {tc} · Go to frame" chip otherwise.
- **Shortcuts in draw mode:** load-bearing: `transportLocked` makes the player's `handleKeyDown` return false and the viewer skips the forward while
  `forms.slot(assetId).draw` is set (focus does not move to an SVG on pointerdown, so a target attribute alone is not enough). `data-owns-keys` on the
  overlay is belt-and-braces. ⌘/Ctrl+Z
  undoes the last stroke (player keys already ignore modifiers); not in a text field (Lightbox rule). Space on the Done button still activates the button.
- **Escape layering:** popups/confirm -> draw mode (first Escape leaves draw mode and KEEPS the strokes; focus to the Draw toggle) -> dirty-form hold (existing) ->
  viewer. This deliberately differs from the Lightbox (which discards); flag it in the PR as owner-visible. Implemented inside `forms.escape()` so the viewer's
  keydown-capture snapshot stays the single decision point (Base UI double-calls `onOpenChange`).
- **Pointer events over `<video>`:** the overlay sits inside `video-picture-box`; the box keeps `pointer-events-none`, the SVG takes `pointer-events: auto` only in
  draw mode; letterbox bands never start a stroke (`picturePoint` returns null outside the box). `touch-action: none` on the SVG in draw mode only (otherwise
  page scroll on phones breaks). `onPointerCancel` ends the stroke; `singlePointer: true` (video only) ignores a second finger — the Lightbox interleaves two
  pointers into one stroke today: pin it in 6a, fix later.
- **ResizeObserver / letterbox:** normalise against the SVG's own `getBoundingClientRect()` at pointer time (it is the picture box in viewport space), not
  `offsetLeft` (layout, not transformed). Draw mode waits for `videoWidth > 0` (never author in the fallback box). Fullscreen re-measures via window resize (already).
- **High DPI:** SVG, so crisp at any DPR; widths are CSS px with non-scaling stroke. No canvas, no DPR scaling code.
- **Touch:** toolbar targets 44 px (`pointer-coarse:min-h-11`, the player's COARSE); the stage on phones is `max-h-[55dvh]`, so the toolbar sits under the
  player, not over the picture. The marker lane is inert on touch already; selecting a note from the list seeks and shows its drawing.
- **Undo:** stroke-level only (Undo button, ⌘Z), no redo, matches the Lightbox. Undo while confirming does nothing.
- **Selected note display:** fetch on select; render only while paused on `drawingFrame`; during playback the drawing hides (ink from frame 100 over frame 2000 is wrong).
  Selection seeks to `drawingFrame`, so selecting shows it at once.
- **Notes count, markers, filters:** markup changes none of them (count = open roots; filters by status/visibility). The pinned-edit rule from 5b covers an
  edit-drawing form whose note is filtered out. Marker shows a pen glyph when `hasMarkup`. A tombstone has `hasMarkup: false`, so no glyph and no fetch.
