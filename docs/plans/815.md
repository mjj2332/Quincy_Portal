# #815 — Review links: show the full link with a Copy button

Owner decision (2026-10-12): store the link secret in **plain text** beside the existing hash. Accepted risk: anyone with database read access can open every review link. Verification still uses the hash only. Settled from blind Opus + Codex plans.

## Schema (migration 0073, owner applies)
- `ALTER TABLE client_links ADD COLUMN token_secret text CHECK (token_secret IS NULL OR length(token_secret) >= 1);` — additive, nullable, no default, no backfill. Check migration-number claims first (`docs/maps/new-table.md` §2). Journal entry idx 73. `schema.ts` `clientLinks.tokenSecret`.
- Existing review and delivery rows stay NULL.

## Worker
- `lib/review-links.ts`: create and `replaceReviewLinkToken` write `token_secret` with `token_hash` in their existing audited batches. **Revoke sets `token_secret = NULL`** (a revoked link never opens again). Move `linkUrl` here as the one URL builder. `loadReviewLinkDtos(..., origin)` selects `token_secret` and returns `url` = built URL when a secret exists and the link is not revoked, else null. Audit meta never contains the token.
- `routes/review-links.ts`: create/replace pass the token; list and `oneLink` pass `APP_ORIGIN`; create/replace keep top-level `{ link, url }`, both from the same DTO. Every review-link response sends `Cache-Control: private, no-store` — set per handler (or inside `admit()` if every handler calls it), never as router-wide middleware (lesson "Hono router-wide middleware leaks across sibling mounts"); run `route-manifest.test.ts`.
- MCP: review-link routes stay off `mcp/route-allowlist.ts`.

## Shared
- `reviewLinkDtoSchema` gains required `url: z.string().url().nullable()`.
