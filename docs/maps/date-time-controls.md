## Rules (`docs/adr/0011-every-subtask-has-a-range.md`, `docs/adr/0016-every-subtask-end-is-a-moment.md`)
- Every Subtask has a range; no unscheduled or due-only state (0011). 0011's "one day at the shortest" is **amended** by 0016: the start only has to be before the end, by instant.
- Every start and end is a Sydney civil date-time; the date-only kind is retired (0016). A picked day with no time takes 09:00 for a start, 17:00 for an end: `SUBTASK_START_PRESET_TIME` portal/packages/shared/src/checklist-schedule.ts:12, `SUBTASK_END_PRESET_TIME` portal/packages/shared/src/checklist-schedule.ts:14 = `DEADLINE_PRESET_TIME` portal/packages/shared/src/project-deadline.ts:14.
- `DateTimeField variant="range"` is the only Subtask-range picker (0016). The server refuses a date-only end with `subtask_schedule_time_required`.
- Default range = shoot date 09:00 through the Deadline at its own time: `defaultSubtaskRange` portal/packages/shared/src/default-subtask-range.ts:44 (fallbacks in its doc comment), `defaultSubtaskRangeDto` portal/packages/shared/src/default-subtask-range.ts:95; the web reaches it through `projectDefaultFromFacts` portal/apps/web/src/lib/date-time-range.ts:84.

## Popup placement and the selected day (#587)
- **Placement.** `DateTimeField` and `SubtaskScheduleControl` take `popupCollisionAvoidance` / `popupCollisionPadding` (a value, or a function called once per open). `SHELL_AWARE_SHIFT_AVOIDANCE` and `shellAwarePopupPadding()` (`lib/date-time-field.ts`) are the shift-below-the-shell-header policy. Full shift opted in: New shoot's Deadline, the Timeline Due cell (`GanttSubtaskDueCell`), the bar picker (`ProductionGanttScheduleEditorPopover`), the Timeline Project Deadline cell (`ProjectDeadlineCell` via `GanttDeadlineCell`) and, since #597, the Dashboard Table's Deadline cell (same `ProjectDeadlineCell`). Padding only (default avoidance, #597): the Project header Deadline (`ProjectHeaderDeadline`) and the Checklist (`SubtaskScheduleControl`). `shellAwarePopupPadding()` measures the top from an open Project sheet, else the shell header. A padding callback is re-read on `resize` while open (`useReresolveOnResize` `lib/use-reresolve-on-resize.ts`, #602). The three-column stack (calendar, shortcuts, time column) stacks below 721px, the same width as the calendar's 44px cells (`popup-breakpoint.contract.test.ts`, #602).
- **Selected day.** `PopupFrame` (`quincy/date-time-field/PopupFrame.tsx`) writes the body's `scrollTop` so the `reveal` day (the picked day, or a range's active end) and the focused element are fully visible and clear of the fade. Pure solve: `scrollTopClearOfFade` with `required` items; when required items conflict, the `priority` item (the focused control) wins over the reveal day. Tests: `PopupFrame-reveal.dom.test.tsx`.
- **Open-time snaps and the fade (#674).** At open `PopupFrame` passes the preset rows' tops (and 0) as `snaps`; `scrollTopClearOfFade` resolves each r > 0 to `floor(max(r - fade, r / 2))` so the row rests clear of the top band (0 stays 0), and the smallest clear one wins. The body fade is `--space-5` (24px) at every width (was 32px below 721px, #597: with it the row-clear and pressed-slot rules were unsatisfiable). The pressed time slot and the active shortcut chip (`aria-pressed`) are `noSliver`. Tests: `lib/date-time-field.test.ts`, `PopupFrame-presets.dom.test.tsx`. Never `scrollIntoView` in popups.
- **Range shortcuts set the active end (#683).** In the range popup Today, Tomorrow, This week and Next week set only the end the Start | End toggle is on (`pair` of `buildRangeShortcuts({ today, projectDefault, active })`, `lib/date-time-range.ts`); Project default (`scope: "range"`) is the only one that sets both. `applyRangeShortcut(row, active, current)` holds every collision rule and returns `"keep"` for an untouched end, which `pickShortcut` leaves whole (typed text, fold choice). START with a new start on or after the end: the end moves to keep the old duration, in wall-clock (civil) minutes so 09:00 / 17:00 survive a DST change. END with a new end on or before the start: the start becomes the shortcut's own start (never the past). An empty, invalid or already inverted other end is filled from `pair`. Sublabels show `momentLabel` of what the shortcut sets on the active tab (`Wed 7 Oct · 09:00`); Project default keeps its span. Pressed compares the active end only (Project default needs both), and two chips that set the same moment (Today and This week on START) both read pressed, so `ShortcutList` takes `activeId` as one id or a list. Tests: `lib/date-time-range.test.ts`, `DateTimeField-range.dom.test.tsx`.
- **TIME below the fold at open (#677).** `DateTimePopup` and `DateTimeRangePopup` mark their TIME `Field` `data-time-boundary`; at open `PopupFrame` passes its input and label as `boundaries` and the preset chips as `chips`. If the #674 landing already leaves the input clear of the bottom band and the label uncut by the body's edge it stands. Otherwise the smallest whole scroll with every input wholly below the body, no `noSliver` item slivered and no chip crossing the top fade's inner edge (a row tail wholly inside the fade is fine) wins; none valid keeps the #674 landing. A label wholly inside the bottom band is allowed (the "more below" cue). At 390: Table Today/Tomorrow and Checklist 102; no-shortcut and Next week stay at 50; a body that does not scroll (1280) stays at 0. Open only: selection and focus solves are untouched. Tests: `lib/date-time-field.test.ts`, `PopupFrame-presets.dom.test.tsx`.

## Time column scroll and the pressed slot (#662)
- **No sliver, either fade.** `scrollTopClearOfFade` portal/apps/web/src/lib/date-time-field.ts takes `noSliver` rects (the pressed slot): never required clear, but never left partly inside the top band `min(fade, s)` or the bottom band `min(fade, max - s)`. Chosen: smallest clear snap; else, with `snaps`, the smallest clear whole scroll, without them the clear whole scroll nearest the current `scrollTop`; else the #630 choice (required and `priority` items win).
- **Reveal, then focus.** `TimeColumn`'s arrow-key handler (`onKeyDown`) calls `reveal(el)` before `el.focus({ preventScroll: true })`, because `PopupFrame`'s `focusin` solve measures the slot where focus lands. `reveal` passes the pressed slot as `noSliver`.
- **Phone fade is `--space-5` (24px)** on the column's `ScrollArea`: 24 + 44 + 4 + 44 + 24 = 140 <= 144 (`h-36`), so a pressed slot and its adjacent row both fit clear of the fades.
- **No re-centre after a pick.** `pickedRef` skips the next centre for the slot a pointer or Enter pick just chose (null if already pressed). Open, a complete typed time and a 721px crossing still centre.
- Header Deadline close goes through `closePopover` in `ProjectHeaderDeadline.tsx`, which focuses the trigger first (see docs/lessons.md § "Adopting base-nova's sidebar", P3, #662).
- Lessons: docs/lessons.md § "A pressed time slot under either fade reads as a grey bar, and focus before reveal jumps the body". Guards: `TimeColumn.scroll.dom.test.tsx`, `lib/date-time-field.test.ts`, `ProjectHeaderDeadline-sheet.dom.test.tsx`.
